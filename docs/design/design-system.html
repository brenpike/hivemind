Swarm Glyph

Hivemind design system

The colors, type, spacing, components and motion behind the Hivemind website, on one page, drawn by the real stylesheet and the real swarm engine.

Live formation: hero. The swarm spells the wordmark above. It first draws one alien glyph per letter, then, 1.5 s after the swarm starts, each letter morphs into its English shape left to right, 0.16 s apart, and lights up as its particles lock in. Tap the wordmark to replay it.

Move or touch to scatter the swarm. Press and hold to call it to you. Tap a heading to re-encode it.

01 Start here

How to use this page

Every swatch, font sample and component below is rendered by the production files, so what you see here is exactly what the website ships. Each component comes with markup you can copy.

Read me first

Viewing this page

  • From the repo root run npm ci, then npm run build, then open docs/design/design-system.html directly in a browser. No server is needed.
  • If web/scripts/main.js is missing (not built yet), the static styles still render. The head script drops swarm-live after 4000 ms, so all text stays readable; only the motion is gone.
  • This page lives in the repo only. It is not deployed and is never linked from the website.
  • The source of truth is web/styles/main.css (look) and web/src/main.ts (motion). If this page and those files ever disagree, the files win.
  • This page loads main.js as a classic script, because browsers block module scripts opened from file://. That works only while main.ts has no import or export. If it ever gains one, this page needs type="module" and a local server.
Term Plain meaning
tokenA named value reused everywhere, such as --violet. Change it once in :root and every use updates.
componentA reusable piece of markup plus its class names, such as a card or a button.
modifierAn extra class with a double dash that varies a component, such as tag--ember.
breakpointA screen width where the layout changes. This system uses 399 px and below, 640 px and up, and 1024 px and up.
clamp()clamp(min, preferred, max): a size that scales with the screen but never leaves the min to max range.
formationThe shape the particle swarm takes while a section is in the middle of the screen.
decodeThe effect where a heading or line starts as alien glyphs or random letters and resolves into real text.
contrastHow readable text is on its background, as a ratio. WCAG AA asks for at least 4.5:1 for normal text and 3:1 for large text.

02 Color

Color tokens

All colors are CSS custom properties in :root of main.css, read with var(), for example var(--violet). The look is a near black void with three neon accents: violet, cyan and ember. Each accent has a lighter -text twin for readable type.

  • Void

    --void #05040d

    Page and canvas background. Also the text color on the primary button and the skip link.

  • Violet

    --violet #8b5cff

    Main accent: glyphs, glows, borders, the start of every gradient, cluster 2. Not for body text.

  • Cyan

    --cyan #29e7ff

    Focus ring, list dots, the end of every gradient, cluster 1, alternate glyph color.

  • Ember

    --ember #ff7a45

    Heat: the decode flash, the flare signal, cluster 4. Used sparingly.

  • Hot

    --hot #f4f1ff

    Headings, the wordmark, the skip link fill, the hub cluster 0.

  • Text

    --text #ece9ff

    Default body text.

  • Dim

    Secondary text: plate intros, nav links at rest, notes, descriptions.

  • Violet text

    Readable violet: solution kickers, violet tags, code keys, the command prompt mark.

  • Cyan text

    Readable cyan: kickers, eyebrows, inline code, table headers, contents numbers.

The stack rule

Inside a .section--tight, every direct child of .wrap or .flow after the first gets 1rem of space above it, the same as the card grid gap. You never add spacing by hand.

The selector is wrapped in :where(), so it counts as one class. That decides who wins a tie: a component margin declared later in main.css (such as .cta--section or .note) wins, while a component declared earlier (such as .subpanels, .install-grid or .cta) loses its own top margin when used as a direct child.

A block after a .plate collapses into the plate's larger 1.75rem bottom margin. The homepage has no .section--tight, so the rule never touches it.

:where(.section--tight) .wrap > * + *,
:where(.section--tight) .flow > * + * { margin-top: 1rem; }

09 Formations

The swarm follows the page

Live formation: ambient (this section). Every particle drifts free with a wandering steer, flocks loosely with its neighbors, and is pulled back if it strays 30 px past the edge of the screen. Any section without a known formation behaves this way.

How a section takes over

A section becomes active when it crosses a thin band in the middle of the screen (an IntersectionObserver with rootMargin: '-48% 0px -48% 0px'; a scroll listener does the same job in old browsers). Each switch restarts the formation: the pull toward the new shape eases in over 1.6 s and never drops below 12%. If a formation's target is missing (no wordmark, no .flow, no [data-orbit]), the swarm falls back to free drift. Without #agent-stage the agents formation uses the whole screen.

11 Live formation: workflow

A stream through the beats

When this section reaches the middle of the screen, the swarm pours down a wavy spine in the left gutter, slowing and glowing at each numbered beat. The beats below describe the formation itself.

  1. Join the spine

    The spine runs down the middle of the gutter, at half of the .flow left padding (var(--gut)).

  2. Stream

    Each particle travels at 60 to 150 px per second, spread up to 12 px to either side of the spine (7 px below 640 px), with the spread pulsing by up to 35%. Between beats the spine curves left and right, up to 26 px.

  3. Slow at each beat

    Each beat has a node 34 px below its top. Within 70 px of a node, particles slow to as little as 20% speed; within 15 px they turn ember or hot.

    The numbered disc is CSS: a counter on .beat::before.

  4. Loop

    A particle that leaves the bottom re-enters at the top. A bright flare rides the spine, crossing the visible stretch about every 9 s.

13 Motion

Motion guidelines

Motion has two layers. The canvas swarm behind the page (main.ts) and the text decode on headings and intros (main.ts plus CSS). CSS transitions only move or fade things (transform and opacity); the only color animations are the two short flash keyframes.

Live demo: xg

Tap this heading to re-encode it

Headings with xg start as alien glyphs and resolve letter by letter, each with a short ember flash. After the first decode, a tap or click replays a shorter one.

Live demo: xs

Scramble decode

Text with xs starts as random Greek, Cyrillic and box drawing characters. A bright ember front sweeps through from the start, fast at first and slowing at the end, and the real letters appear behind it.

  • Boids

    A classic flocking recipe: each particle steers by three simple rules (keep apart, match neighbors' heading, move toward the group) plus a pull to its formation target. Complex swarm shapes come from these local rules.

  • Spatial hash

    To find neighbors fast, the screen (plus a 120 px margin) is cut into 28 px cells, and particles are sorted into cells each frame. A particle only checks its own cell and the 8 around it.

  • Glyph lattice

    24 alien glyphs drawn on a 20 by 20 grid, used both as SVG symbols for the text decode and as canvas paths. The wordmark letters and the glyphs are painted offscreen and sampled on a staggered grid of points that particles fly to.

  • Scramble

    The decode puts an aria-hidden copy of the text on top, split into one span per character, and lets each span flicker before showing the real letter. The real text stays in the page, so screen readers and copy and paste are never affected.

  • Glow sprites

    Each color is pre-drawn once as a 64 px soft radial dot with a white core. Particles are copies of these images, drawn with lighter compositing so overlaps add up into brighter light, like real glow.

  • Trails

    Instead of clearing the canvas, each frame paints a translucent void color over it (26% per frame at 60 fps), so moving particles leave short fading streaks.

  • Time based motion

    Every movement is multiplied by dt, the seconds since the last frame, so the swarm moves at the same speed on a 60 Hz or a 120 Hz screen.

  • Smoothstep

    The easing curve t x t x (3 - 2t): starts slow, speeds up, ends slow. Used for formation ramp in and the letter morphs.

  • Real text first

    The canvas and every overlay are decoration marked aria-hidden. Without JavaScript the page is complete and readable.

14 Reduced motion

When people ask for less motion

Operating systems have a "reduce motion" setting. The site honors it completely, and switches live if the setting changes while the page is open.

Layer Under reduced motion
Head gateNever adds swarm-live, so the page starts static.
CSSEvery transition and animation is off, smooth scroll becomes instant, the hint line is hidden, the wordmark is solid hot with its violet glow, and decode overlays are hidden.
CanvasOne still picture of the agent graph: hub, spokes and up to 1200 particles (450 below 640 px). Labels appear only on pages with #agent-stage; elsewhere the graph is drawn faintly (alpha 0.4) across the whole screen.
CardsHover or tap still lights a cluster; the still picture is redrawn with that cluster lit.
This pageAll demos here are static: no wordmark sequence, no decode, no formations.

Fallbacks

If the canvas, its 2D context, requestAnimationFrame or the glow sprites are unavailable, the engine removes swarm-live and the page stays static. If main.js never runs, the head gate's 4000 ms timer removes swarm-live, because the engine never added swarm-ready. Without IntersectionObserver there is no text decode.

Accessibility checklist

  • Text meets WCAG AA contrast (see the color table). Use the -text colors for type.
  • Every tap target is at least 44 px tall (buttons 48 px).
  • Keyboard focus shows a 2px cyan outline, 3px away from the element.
  • Scrolling boxes (.table-wrap, .code-panel) get role="region", an aria-label and tabindex="0".
  • Text drawings get role="img" and a plain words aria-label.
  • Decoration is aria-hidden; CSS generated marks use the content: ... / "" form so screen readers skip them.
  • Links that open a new tab use target="_blank" rel="noopener noreferrer".
  • Respect notches: side and top padding use env(safe-area-inset-*).

Writing style

  • Plain, short sentences. The themed words (overlord, drone, brood) are explained on first use.
  • Headings in Title or sentence case; CSS turns labels uppercase, so type them normally.
  • No em or en dashes.
  • Every claim traces to the repo root README.md.
