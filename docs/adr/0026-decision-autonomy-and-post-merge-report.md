# Decision autonomy and post-merge decision report

**Status:** accepted — 2026-06-17

## Context

The overlord historically surfaced a large volume of judgment calls to the user (the Overmind) for confirmation — most acutely during the local and GitHub review-remediation cycles, where each planner-escalation, diminishing-returns advisory, version-bump-type inference, and remediation-approach choice became an interrupt. Many of these were decisions the overlord could make safely on its own: the recommended action was contained, reversible, and carried no architectural or safety blast radius. Surfacing them anyway traded the overlord's autonomy for live oversight the user did not need to exercise, and buried the genuinely consequential decisions in the noise.

The design recorded here shifts the default posture: judgment calls the overlord previously surfaced for confirmation are now taken on the user's behalf and recorded, leaving only genuine ambiguity-with-risk for the user. The normative mechanics — the tier membership lists, the 2x2 cells, the promotion-gate categories, the disposition vocabulary, the journal entry shape, and the post-merge report trigger conditions — live exclusively in `plugin/governance/decision-autonomy.md` as the authoritative runtime home. This ADR records the hard-to-reverse, surprising-without-context decisions and their rationale; the governance doc executes them. The pointer is one-way ADR → governance.

## Decision

1. **Two decision tiers split always-surface from auto-decide.** Tier-A decisions (all safety rails, router ambiguity, resume/version-skew doors, brood strain approval, retry-exhausted tool errors, genuine fact-needed blockers, and ALL merge recommendations) are ALWAYS surfaced, exactly as before this posture existed. Tier-B decisions (planner-escalation routing, diminishing-returns early-exit, autonomous validation remediation, inferable version-bump type, root-cluster zoom-out routing, and confident remediation-approach choices) are auto-decided and journaled by default.

2. **An Autonomy 2x2 governs every Tier-B decision: recommendation strength (strong | weak/none) crossed with the promotion gate (clean | trips).** Strong recommendation + clean gate → DO THE WORK NOW (`did-now`). Weak/no recommendation + clean gate → DEFER-with-scope as a tracked follow-up (`deferred`). Any recommendation + gate trips → SURFACE (`surfaced`). A confident fix is never downgraded to a deferred follow-up; defer is the fallback for the ABSENCE of a strong recommendation, not a substitute for one.

3. **The promotion gate evaluates the RECOMMENDED action, not the option set.** The gate trips — forcing a surface — only when the recommended action is irreversible, carries architectural blast radius, or is safety-relevant (any Destructive Fix category 1-10 per `plugin/governance/safety-rails.md`). A heavy or architectural ALTERNATIVE being on the table does NOT promote the decision: if the recommended action is contained and the gate is clean, the overlord acts on it even though a bigger option exists.

4. **The decision journal is RECORDED JUDGMENT made observable, not new determinism.** Each Tier-B decision (and, for a complete audit trail, each Tier-A surface) is appended as one entry to `event.outputs.decisions[]` on the bounding state-result event — the same sanctioned free-form `event.outputs` write the proactive recurrence-origin marker already uses. This introduces no new workflow state, no workflow-graph change, no new run status, and no routing through `hivemind:mark-intent-fallback`. This follows the ADR-0025 precedent: judgment made observable after the fact over GitHub/ledger ground truth, not a new control-flow primitive. `decisions[]` is a free-form `outputs` key, not a new required ledger field; the canonical `event.outputs` shape is single-sourced in `plugin/references/run-ledger-schema.md`.

5. **A deferred, CHAT-ONLY post-merge decision report fires for runs that auto-decided.** After the PR for a run merges, the overlord surfaces a report recounting every decision it made on the user's behalf, rendered in the CONSUMER project's ubiquitous language. The report is CHAT-ONLY — it is rendered to chat and never written to disk as a content file (no `decision-report.md`). It is deferred-on-merge: produced not at merge time but on a subsequent session start, when the Resume-On-Start scan derives an AWAITING-REPORT run and observes the PR as `MERGED` or `CLOSED`. A run is AWAITING-REPORT when all hold: a PR is derivable from a recorded event output, the journal carries at least one `did-now`/`deferred` decision, and the run dir does not yet contain the zero-byte `.decision-report-done` marker. The report fires ONLY for runs with ≥1 `did-now` or `deferred` decision — a journal holding only `surfaced` entries produces no report. The EXISTENCE of the zero-byte `.decision-report-done` marker the overlord `touch`es in the run dir is the SOLE idempotency marker — there is NO ledger marker, NO `decision-report.md` content file, no new `run.status` value, and the run-status enum is unchanged. The PR is derived from the persisted `open_pr` event output (`event.outputs.pr`) for a standard-delivery run AND from the persisted `pr_branch_preflight`/`intake` event output for a `pr-feedback-remediation` run (which has no `open_pr` state) — both via the same free-form `event.outputs.pr` convention, closing issue #302.

6. **This ADR SUPERSEDES ADR-0003.** Planner escalation during review loops is no longer an immediate hard stop that returns to the user. It is a Tier-B decision auto-routed to the cerebrate remediation state and journaled, surfacing only when the promotion gate trips (which, being architectural by construction, it typically does for a genuine approach-level zoom-out).

## Considered Options

| Option | Rejected because |
|---|---|
| Surface everything — keep the status quo where every judgment call is an interrupt | Buries the genuinely consequential decisions in a high-volume stream of safe, contained ones; the review cycles in particular generate enough planner-escalation, advisory, and approach choices that the user's oversight is spent on decisions the overlord can make safely. The signal-to-noise cost outweighs the oversight benefit |
| Auto-decide without any record | Removes the user's ability to audit what was decided on their behalf, defeating the trust required for the autonomy shift; an unrecorded autonomous decision is indistinguishable from a silent scope expansion |
| Persist a new run-status / ledger marker for the post-merge report | Duplicates an idempotency signal the zero-byte `.decision-report-done` marker already provides, adds a new `run.status` value and persistence surface, and couples report state to the ledger when GitHub PR state plus marker presence already determine it — the same single-source-of-truth reasoning ADR-0025 applied to the recurrence ledger |

## Consequences

- **More overlord autonomy at the cost of reduced live oversight, mitigated by the post-merge report.** The trade-off is deliberate: the overlord now acts on contained Tier-B decisions without interrupting the user, and the user's oversight moves from synchronous (confirm each call live) to asynchronous (review the full recounting after merge). The mitigation is structural — the chat-only report fires for any run that auto-decided (≥1 `did-now`/`deferred` decision), recounting each decision as situation / options / trade-offs / decision / why, so no autonomous decision escapes eventual review.
- **The merge action always stays with the human.** The overlord NEVER merges; ALL merge recommendations are Tier-A and always surfaced. Autonomy never extends to merging — it covers only the contained judgment calls along the path to a mergeable PR.
- **The promotion gate is evaluated against the recommended action, producing deterministic routing.** A single judgment per decision — is the recommended action irreversible, architectural, or safety-relevant — routes it to auto-take or surface. A heavy alternative on the table does not change that routing, which keeps confident contained fixes from being spuriously promoted.
- **The journal adds observability without new determinism.** Because `decisions[]` rides the existing free-form `event.outputs` path, the workflow graph, run-status enum, and ledger required-field set are all unchanged. The decision trail is reconstructable from the ledger event, consistent with how ADR-0025 made recurrence state observable over ground truth rather than via a new persisted artifact.
- **ADR-0003's immediate-stop rule is retired.** Planner escalation joins the Tier-B set and is journaled like any other auto-decision, surfacing through the promotion gate rather than as an unconditional mid-loop hard stop.

References: `plugin/governance/decision-autonomy.md`, `plugin/skills/decision-report/`, `plugin/references/run-ledger-schema.md`; supersedes ADR-0003; extends the ADR-0025 recorded-judgment precedent.

## Amendment — 2026-09-18 (a fourth disposition, `recorded`, joins the vocabulary; the report's fire condition widens)

Decision 2 and Decision 5 above name three dispositions and read the weak/no-recommendation + clean-gate cell as DEFER-with-scope to a tracked follow-up. That cell now carries TWO destinations, and the vocabulary gains a fourth disposition.

**`recorded`.** A finding that was adjudicated and deliberately not actioned — the behavior is inherited rather than introduced by the change, its impact is bounded and understood, and the obvious remediation was considered and rejected on the merits — resolves to `recorded`: the reasoning is written into the repository next to the code it concerns, carrying root cause, bounded impact, and why the obvious remediation was rejected, and no tracker entry is created. `recorded` is NOT a silent drop. Its scope obligation is IDENTICAL to `deferred` — full root-cause scope, linked threads, bounded-impact note — and only the destination differs. `deferred` asserts that someone will act; `recorded` asserts that we decided, and here is why. Filing a decision as a tracked issue inflates the backlog and buries the reasoning away from the code, which is why recording is preferred when the finding is a decision rather than work.

**Additive over the existing journal — no new determinism.** `recorded` is a fourth permitted VALUE of the existing per-entry `disposition` field on the free-form `event.outputs.decisions[]` journal. It introduces NO schema change, NO new ledger field, NO new workflow state, NO workflow-graph change, and NO new `run.status` value, and it is not routed through `hivemind:mark-intent-fallback`. This preserves Decision 4 exactly as written: the journal remains recorded judgment made observable after the fact, riding the same sanctioned free-form `event.outputs` write, with the canonical `event.outputs` shape still single-sourced in `plugin/references/run-ledger-schema.md`.

**The post-merge report's fire condition widens.** Decision 5's AWAITING-REPORT derivation and firing condition required at least one `did-now` or `deferred` journal entry. Both now read `did-now`, `deferred`, or `recorded`. A run whose journal holds only `surfaced` entries still produces no report. Everything else in Decision 5 is unchanged: the report stays CHAT-ONLY with no file written to disk, stays deferred-on-merge to a subsequent session start, and the zero-byte `.decision-report-done` marker remains the SOLE idempotency signal. The widening closes the gap the fourth disposition would otherwise open — a run that adjudicated findings into records, and nothing else, is exactly a run whose autonomous decisions warrant asynchronous review.

The NORMATIVE home for the disposition vocabulary, the 2x2 cell, and the report trigger conditions is `plugin/governance/decision-autonomy.md` (`## Disposition Vocabulary`, `## The Autonomy 2x2`, `## Post-Merge Decision Report Trigger`), with the recording destination itself defined in `plugin/governance/remediation-doctrine.md` (`### Recorded Residual`). This amendment records the decision and rationale; the governance docs execute them. **The decision summary in this amendment is a NON-AUTHORITATIVE ECHO**, written so the rationale reads as a whole — never a second source of the mechanics. Where this echo diverges from, narrows, or widens the governance text, THE GOVERNANCE DOCS GOVERN and the echo is stale prose to be corrected. In particular, the three conditions that qualify a finding as `recorded` are CONJUNCTIVE — all three must hold — and an agent applies them from governance, never from this summary. The pointer stays one-way ADR→governance.

No new ADR is created for this decision: this ADR is its correct home, and ADR ordinals collide across parallel worktrees.

This amendment is APPEND-ONLY in the EDITING sense: the original Context, Decision, Considered Options, and Consequences above are left byte-unchanged rather than rewritten in place. It is NOT append-only in NORMATIVE FORCE. Where this amendment supersedes a clause above — Decision 2's three-disposition vocabulary and its weak/no-recommendation + clean-gate cell, and Decision 5's `did-now`-or-`deferred` AWAITING-REPORT and firing condition — THIS AMENDMENT GOVERNS and the superseded clause is historical record, not an enforceable rule. Every clause this amendment does not name stands in force as written, including the ADR-0003 supersession. Status remains accepted.

## Amendment — 2026-09-18 (adjudication of PR #360 FINDING 1, and a recorded residual on the journal's missing destination field)

External review of PR #360 raised FINDING 1 ([thread](https://github.com/brenpike/hivemind/pull/360#discussion_r4047777159), with the related [thread](https://github.com/brenpike/hivemind/pull/360#discussion_r4047777167)): the doctrine requires a durable repository record for a recorded residual, but — the finding argued — no execution path can produce one, because `local-reviewer` has no `recorded` fix-ledger status, `github-reviewer`'s Output Contract returns no record location, and the cerebrate excluded the tail from executable plan steps. This amendment adjudicates that finding, records what was fixed in response, and records the remaining gap as a residual under the very doctrine the finding was raised against.

**The general premise is refuted; the bar it applies is one `deferred` has never met.** The reviewer measured `recorded` against a standard of mechanical producibility that no disposition in this repo satisfies. Nothing in the plugin files a tracked issue either: `gh issue create` appears eleven times under `plugin/`, and every occurrence is confined to `plugin/skills/prd-to-issues/SKILL.md` and `plugin/skills/prd-to-issues/scripts/subissue-ops.sh` — a PRD-slicing skill, which is not a review-remediation actor. The cerebrate's only issue-related grant is the read-only `Bash(gh issue view *)`. The fix-ledger status vocabulary (`open` → `fixing` → `fixed` | `regressed`, `fixed` → `cycling`) carries neither `recorded` nor `deferred`. So "no actor is mechanically contracted to write the destination" describes this repo's standing intent-based governance posture (ADR-0006) applied identically to both non-acting dispositions. It is not a defect introduced by the fourth disposition, and `recorded` is not held to a bar `deferred` clears.

**Two true sub-claims inside the finding were fixed this cycle, at commit 86d2914.** First, the cerebrate's plan-block rule now makes a repository-record destination an EXECUTABLE plan step with an owner and an exact file scope — a recorded residual is a file someone must actually write, so it is a step like any other and never prose-only — while a tracked issue, not being a repository write, is named in prose as an explicit orchestrator obligation. Second, `plugin/governance/remediation-doctrine.md` (`## Defer-with-Scope`) now states that the actor leaving a finding unfixed OWNS its destination: the record written or the issue filed BEFORE the loop terminates, never merely named, with that actor carrying the destination's LOCATION in its own record of the decision. Both are INTENT-BASED obligations on agents that read governance, not mechanized guarantees; nothing validates them at runtime.

**Recorded residual: the journal entry shape carries no dedicated destination field.** The per-entry field list in `plugin/governance/decision-autonomy.md` (`## Decision Journal`) is unchanged from `main` except that the `disposition` enum gained its fourth value; no destination field existed before this change and none was added. A record's location therefore lives only inside the entry's free-form `decision` / `rationale` prose, so a lazy entry can journal `recorded` while naming nowhere, and nothing mechanically catches it. The three conjunctive conditions of `### Recorded Residual` are argued individually:

- **Inherited, not introduced.** The absence of a destination field predates this change and applies to every disposition. `deferred` has always had to name its tracked follow-up in the same free-form prose. The field list this change touches differs from `main` in exactly one line, and that line is the enum.
- **Bounded and understood impact.** The consequence is observability and audit only. The `disposition` value's only consumers are the post-merge report's fire condition (an auto-set membership test, `did-now` | `deferred` | `recorded` versus `surfaced`) and the report's display tag; no control flow anywhere reads a destination, because none is recorded as structure. The real guard against a nowhere-record is the silent-drop prohibition in `## Defer-with-Scope`, which already binds both destinations and is unaffected. The `hivemind:decision-report` skill was additionally hardened at 86d2914 to state plainly that the entry's own text is its ONLY source for a destination and that inventing one is a false audit line — so the gap degrades to a missing detail, never a fabricated one.
- **Obvious remediation considered and rejected on the merits.** The obvious fix is a required `destination` field validated by the ledger engine. It was rejected because `hivemind:record-state-result` records `outputs` VERBATIM and validates only that it is a JSON object — so a "required" field would be prose-enforced exactly like the obligation it replaces, buying a schema line and no enforcement. Building real enforcement would mean a new prose-scanning policy check, and this repo built precisely that class of check (CHECK 15), hardened it across three follow-up commits (4cd1517, 02139a2, c17243f), and then reverted it wholesale at 0fa39cb pending a source-derived successor. Re-introducing the same shape here, before that successor exists, repeats a decision already taken against.

**The counter-argument, stated plainly.** A reader may reasonably hold that the "inherited" judgment is too convenient here: adding a fourth disposition whose DEFINING feature is its destination raises the bar on carrying that destination, even though the field's absence is genuinely inherited. `deferred` at least points at a tracker that exists as an external artifact; `recorded` points at a file whose very existence is the claim. That argument is not dismissed. The judgment went the other way because the remediation available today is a schema line with no enforcement behind it, and because the real guard — the silent-drop prohibition plus the newly explicit destination-ownership rule — binds the actor rather than the record format. A field that can be filled with anything would not have caught the failure mode it is proposed to catch.

**Promotion path.** This residual is explicitly not one-way. Per `### Recorded Residual`, a recorded residual whose reasoning is later invalidated is PROMOTED to a filed tracked issue carrying the same full scope. If the "inherited" judgment above is rejected — by a reviewer, by the Overmind, or by an observed nowhere-record in a real run — that promotion is the remedy, and the issue carries this section's root cause, bounded impact, and rejected-remediation reasoning intact. No tracker entry is opened now: this record IS the destination, and issue #353 is explicitly NOT the home, since it owns enumeration replication, a different root.

**What this amendment is.** It is this PR's own new doctrine dogfooded on a finding raised against that doctrine — the first `recorded` disposition applied in anger, written next to the decision it concerns rather than filed as work. That is worth saying plainly. It is not, on its own, evidence that the doctrine works; one application under the author's own judgment proves only that the destination is reachable.

This amendment is APPEND-ONLY: the Context, Decision, Considered Options, Consequences, and the 2026-09-18 fourth-disposition amendment above are left byte-unchanged. It creates no new ADR, adds no normative rule, and supersedes no clause — the normative homes remain `plugin/governance/remediation-doctrine.md` and `plugin/governance/decision-autonomy.md`. Status remains accepted.
