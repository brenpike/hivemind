# Solution design: Lair strain containment

This is the solution design for issue #646, the strain containment part of the Lair, epic #603. It was split from #633 by the user's answer of 2026-11-22 (review record, Decisions asked, "Round 3 questions", Q1). It links the [PRD](../../prds/autonomous-ready-issue-loop.md), [ADR-0045](../../adr/0045-lair-software-factory.md) and the parent [solution design](solution-design.md) rather than restating them, and cites ADR-0045 as "ADR-0045 decision N". The design review is recorded in the [strain containment review record](strain-containment-review-record.md).

It designs the mechanism of the parent design's Seams between the part designs, item 6, which states the requirement and points here. Its inputs are:

- the user's answer 1A of 2026-11-22 at #633's integration review round 1 ([review record](review-record.md), Decisions asked, "Round 1 questions", Q1): #604 builds per-platform containment of `control/` and of the Lair's tmux servers, #608's preflight probe `sandbox` stops the Lair when containment cannot be confirmed, and the merge lane's cache sits under `control/`;
- the ADR-0045 amendment of 2026-11-22, "the Lair's strains can read its key where no sandbox hides its processes" (process reach), with the ADR-0045 amendment of 2026-11-21, "sessions running as the user can forge Lair markers";
- the inherited findings of #633's integration review, mapped under Inherited findings.

For its scope it extends or overrides these parts of the three frozen part designs. Each override lands through the dated solution-design entry under Changes to shared documents.

- [Strain launch](strain-launch-design.md):
  - Contracts and seams, "Strain environment": two names are no longer passed, some values become Lair-set literals (Contracts and seams, "Environment literals"), and the `env -i` words come first in the command string;
  - Components "Strain launch and settings": the launch command is wrapped by the platform launcher, every tmux call names the default server, and "Environment preflight" runs inside the sandbox, in two probe sessions, with the probe `sandbox` and a case id in its stop cause;
  - Components "Start points": in Lair mode, `push-branch.sh` records no upstream and `create-working-branch.sh` changes none;
  - Contracts and seams, "Strain settings": the fragment sets `sandbox.enabled` to false;
  - State and ownership: the spawn record gains the admin folder name, and the preflight folder holds no result file;
  - Trust boundaries, "Strain containment": its statement that a strain can read any file the user can holds outside what this design hides; "Named residual: the tmux global environment" narrows to a strain that escapes containment;
  - Lifecycle steps 2 and 5: spawn starts the sandbox and attaches the forwarder; the head check reads the strain's `HEAD` as data and runs no git in its worktree, and the rescue step only pushes from the main checkout, since a kept worktree is strain-written; clean-up also removes the per-strain folders, by recorded paths only.
- [Claim integrity](claim-integrity-design.md):
  - Components "Lair state root": the state root gains `sandbox/` and `relay.sock`, and `control/` gains `lair.sock`, `probe.sock` and the probe's scratch files;
  - Lifecycle, Start step 3: the socket path check covers the new sockets;
  - Contracts and seams, "Assumptions about #630": Containment of the key and the halt file, Process reach, Tmux reach and Result file per strain are met on Linux by this design, and on macOS as Trust boundaries states.
- [Merge lane](merge-lane-design.md):
  - Contracts and seams, "Assumptions about #630", "A strain writes nothing outside its worktree and the shared object and ref store": met on Linux, and on macOS as Trust boundaries states;
  - Contracts and seams, "Git and tool reads": no Lair git or `gh` call names a path of a strain's layout;
  - Trust boundaries, "Residual: a strain that writes the tick's inputs": it narrows to a strain that escapes containment.

Every other part of the three part designs stands.

Platform facts this design relies on:

- Claude Code's own `sandbox` setting covers shell commands only. Its file tools, MCP servers and hooks run outside it, with the user's full access ([Claude Code sandboxing](https://code.claude.com/docs/en/sandboxing)). So a strain needs an outer wrapper around its whole command, not that setting. The same page says the Linux and WSL2 sandbox relies on bubblewrap and `socat`, and that WSL1 and native Windows are not sandboxed.
- Bubblewrap makes user, PID, IPC, UTS and network namespaces, mounts a fresh `/proc`, a new `/dev`, tmpfs folders and read-only or writable binds, kills the sandbox when its parent dies (`--die-with-parent`), loads a compiled cBPF seccomp program (`--seccomp FD`), and can block the sandbox until a file descriptor has data (`--block-fd`) and report the child's process id (`--info-fd`) ([bwrap(1)](https://manpages.debian.org/testing/bubblewrap/bwrap.1)). A new network namespace holds only a loopback device. Its man page recommends `--new-session`, or a seccomp rule against the `TIOCSTI` ioctl, so a sandbox cannot push input into its terminal.
- Bubblewrap's source ([bubblewrap](https://github.com/containers/bubblewrap), `bubblewrap.c` and `bind-mount.c`): every bind is recursive; a read-only bind is made read-only across its submounts by `mount_setattr` with `AT_RECURSIVE`, or by a remount of each submount listed in `/proc/self/mountinfo`; every bind but `--dev-bind` gets `nodev` and `nosuid`; every mount is marked a slave, "so that we still receive mounts from the real root"; and `--info-fd` gets a JSON object with `child-pid` and the namespace ids.
- A seccomp filter sees each system call argument as 64 bits, while the kernel reads an `int` argument as its low 32 bits. Flatpak's CVE-2019-10063 was a `TIOCSTI` rule that compared all 64 bits, so `TIOCSTI | 1<<32` got through ([NVD](https://nvd.nist.gov/vuln/detail/CVE-2019-10063)).
- A network namespace isolates the abstract Unix socket namespace ([network_namespaces(7)](https://man7.org/linux/man-pages/man7/network_namespaces.7.html)).
- Seccomp cannot see operations requested through io_uring, and `IORING_OP_SOCKET` is io_uring's form of `socket()` ([LWN](https://lwn.net/Articles/1054225/)).
- Unprivileged user namespaces can be blocked. Ubuntu 23.10 added `kernel.apparmor_restrict_unprivileged_userns` and Ubuntu 24.04 turns it on by default; bubblewrap then needs an AppArmor profile ([Ubuntu discourse](https://discourse.ubuntu.com/t/understanding-apparmor-user-namespace-restriction/58007), [Launchpad bug 2046477](https://bugs.launchpad.net/bugs/2046477)).
- Landlock's scope for abstract Unix sockets arrived with Landlock ABI 6, in Linux 6.12 ([kernel Landlock docs](https://www.kernel.org/doc/html/next/userspace-api/landlock.html)).
- macOS `sandbox-exec` is deprecated, and Apple's developer support calls it unsupported for this use ([Apple forum thread 854443](https://developer.apple.com/forums/thread/854443)). A process that already has a sandbox cannot apply another, and a child inherits its parent's sandbox ([Sandboxing on macOS](https://bdash.net.nz/posts/sandboxing-on-macos/)). So a tool that starts its own `sandbox-exec` inside a strain fails.
- On WSL2, Windows programs run through `binfmt_misc` and WSL's `/init`, which finds an interop server on a Unix socket under `/run/WSL`, named by `WSL_INTEROP` or found by process id ([WSL interop](https://wsl.dev/technical-documentation/interop/), [Microsoft Learn](https://learn.microsoft.com/windows/wsl/interop)).
- tmux keeps its default sockets in a `tmux-<uid>` folder under `TMUX_TMPDIR`, or `/tmp` when it is unset; `-L` names another socket in that folder and `-S` takes a full path. Inside a tmux pane, a tmux command with neither flag uses the server that `$TMUX` names ([tmux(1)](https://man7.org/linux/man-pages/man1/tmux.1.html)). `-L default` names the default server.
- `gh` stores its token in the system credential store by default: the Keychain on macOS, the Secret Service keyring (GNOME Keyring) on Linux. `--insecure-storage`, or a store that is not available, keeps it in plain text in `hosts.yml` ([gh auth login](https://cli.github.com/manual/gh_auth_login), [GitHub CLI 2.26.0](https://github.com/cli/cli/releases/tag/v2.26.0)).
- An empty `credential.helper` value resets the list of helpers git has read so far ([gitcredentials](https://git-scm.com/docs/gitcredentials)). `GIT_CONFIG_COUNT` with `GIT_CONFIG_KEY_<n>` and `GIT_CONFIG_VALUE_<n>` adds config entries from the environment ([git commit d8d7715](https://googlers.googlesource.com/jrn/git/+/d8d77153eafdb0fc334e827976f09e4bdff26b58)).
- Claude Code honors `HTTPS_PROXY`, `HTTP_PROXY`, `NO_PROXY` and their lowercase forms, and does not support SOCKS. A variable set in the launch environment wins over the same key in a settings file's `env` ([Claude Code network configuration](https://code.claude.com/docs/en/network-config)).
- Claude Code keeps credentials in the macOS Keychain, and on Linux in `~/.claude/.credentials.json`, which moves under `CLAUDE_CONFIG_DIR` when that is set. `CLAUDE_CODE_OAUTH_TOKEN`, made by `claude setup-token`, is a long-lived token for scripts ([Claude Code authentication](https://code.claude.com/docs/en/authentication)).

Facts this design could not confirm from a source are live-probe assumptions of #604 (Verification strategy, "Live-probe assumptions"). Each one fails closed.

## Requirement

The Lair keeps every strain and remediation strain to what it may reach. A strain reaches only what this section allows. Anything else is out of reach whether or not this design names it. The invariants say what the strain can reach, one per scope bullet of #646; they are never a list of hidden targets.

- **I1, `control/`.** No strain can read, write or delete anything under the state root's `control/` folder: the marker key, the halt file, the lock, the sockets, the merge lane's cache and the decision digest. On Linux the strain's view holds no state root at all: the builder refuses any read-only bind that would show it (Contracts and seams, "Launcher argv"). On macOS the profile denies reads and writes under `control/`, and runs no command outside itself, confirmed by the probe's channel cases; what remains is under both ADR-0045 amendments (Trust boundaries, "Residual: what macOS leaves").
- **I2, services that run commands.** No strain can reach a tmux server, or any service that runs commands outside its sandbox. On Linux `socket()` makes only IPv4, IPv6 and netlink sockets, and `socketpair()` only connected Unix stream or seqpacket pairs, which reach nothing outside the pair. So a strain reaches no path socket, abstract socket, group-openable system socket or vsock service, `/run/docker.sock` included. Its network namespace holds only loopback, and its one way out is the Lair's proxy, which refuses local addresses. Its view holds only named binds, with no FIFO of the host, which the `special-files` case checks at each start. A host socket or device node in a bind stays unreachable: the filter allows no `AF_UNIX` socket, its `/dev` is bubblewrap's minimal one, and every other bind is `nodev`. A FIFO made later under a bound path is the residual "a special file or mount made after the launch". On macOS the profile denies Unix socket connects, loopback TCP, mach services, preference writes, Apple Events and launchd jobs, each with its named exceptions (Components "macOS launcher"), confirmed by the probe's channel cases; what remains is under both ADR-0045 amendments.
- **I3, siblings.** No strain can write another strain's worktree, per-worktree admin folder, per-strain folders, strain record folder, or result, liveness or launch files. This holds for a sibling that starts after it.
- **I4, shared run-or-load config.** No strain can write a shared file that another process later runs or loads as config: the git common directory's `config`, `hooks/` and `info/`, and its `objects/info/`; the main checkout's `.claude/`; `.hivemind/broods/`; the user's Claude Code settings and plugin folder and `~/.claude.json`; the directories on `PATH`; `gh`'s config folder; and `$HOME/.jq`. The rule is the allowlist of I5: a path outside it is read-only or absent, so the list names examples, not the boundary. A strain does write files that git loads as config: its worktree's `.git` file and its admin folder's `commondir`, `gitdir`, `HEAD`, `config.worktree` and `index`. So once a strain's or probe session has started, no Lair process runs git, `gh` or any tool that loads git config with a path of that session's layout (its worktree, admin folder or per-strain folders) as its working folder, in any argument or in its environment. The Lair reads such a file only as checked data (Lifecycle, "Clean-up").
- **I5, the write allowlist.** A strain writes only:
  - its own worktree;
  - its own per-worktree admin folder `<common>/worktrees/<name>/`;
  - the shared object store `<common>/objects/`, with `objects/info/` read-only, and the shared ref store `<common>/refs/` and `<common>/logs/`;
  - its per-strain scratch folder, its per-strain Claude Code state folder and its per-strain Codex home, all under the state root, outside `control/`.

  On Linux it also writes the private tmpfs folders its sandbox mounts, which no other process sees.
- **I6, keyring and session bus.** No strain reaches the session bus, the Secret Service keyring or an SSH agent on Linux. Its GitHub credentials come by the fallback order of Components "Keyring and session bus". On macOS it reaches the user's Keychain through the Keychain service, as any of the user's sessions does.

No invariant rests on an environment value. `PATH` and the user's config paths only choose read-only binds, and the builder refuses any that would show `/`, `$HOME`, the state root or the user's Claude Code folder. The environment literals make the strain's tools work inside the sandbox; the namespaces, mounts, seccomp filter and profile do the containing.

## Components

### Linux launcher

Built by #604. On Linux, WSL2 included, bubblewrap wraps the whole strain command, `env -i ... claude ...`, so `claude`, its hooks, its MCP servers, its tools and every process they start run inside one sandbox.

- **Namespaces.** User, PID, IPC, UTS and network namespaces, each named by its own flag, never a `-try` form that goes on without it. So a namespace bubblewrap cannot make fails the launch.
- **Lifetime.** `--die-with-parent`: the sandbox ends when the pane's process ends. The pane runs bubblewrap as its only process, so no process outside the sandbox reads the pane's terminal.
- **Process view.** A fresh `/proc` for the new PID namespace and a new `/dev`. No Lair process, sibling strain or user process is visible or can be signalled.
- **File view.** Deny by default: the view holds only what the builder names, in this order, each path at its real path and only when present.
  - The root is a fresh tmpfs, remounted read-only (`--remount-ro /`) once every mount below is in place.
  - Read-only binds: the system directories `/usr`, `/bin`, `/sbin`, `/lib`, `/lib32`, `/lib64`, `/libx32` and `/etc`; each `PATH` directory, and the folder holding the resolved target of each link in one; the Lair checkout, and the main checkout that holds `<common>` when that is another folder; git's user config, `~/.gitconfig` and `~/.config/git/`; `gh`'s config folder; the user's Claude Code `plugins/` folder, whose plugin paths are recorded absolute; and the Claude Code views of Components "Claude Code state and auth". Every read-only bind is read-only across its submounts. The builder refuses a read-only bind whose resolved source is or contains the resolved form, by `realpath`, of `/`, `$HOME`, the state root or the user's Claude Code folder, and binds no `PATH` entry under WSL2's Windows drive mounts (Contracts and seams, "Launcher argv", "Wide-bind rule").
  - Nothing else of the host is in the view: `$HOME`, `/run`, `/mnt`, `/media`, `/srv`, the state root and the rest are absent. So `control/`, every sibling's per-strain folders, the user's runtime sockets and WSL2's `/run/WSL` and `/mnt/c` are not in it, nor any host FIFO or mount outside the binds.
  - Fresh tmpfs folders at `/tmp`, `/var/tmp`, `/dev/shm` and `$XDG_RUNTIME_DIR` give the strain private writable scratch. A fresh tmpfs also covers the Lair checkout's `.claude/worktrees/` and `<common>/worktrees/`, so no sibling's worktree or admin folder, a kept one included, is in the view.
  - Writable binds then add exactly the allowlist of I5.
  - A read-only bind covers `<common>/objects/info/` after the writable bind of `<common>/objects/`. The Lair creates that folder before the launch when it is absent.
  - Every bind but bubblewrap's own `/dev` is `nodev`, so a device node on a host file system cannot be opened.
  - The probe's `read-only` and `special-files` cases check the result at each start (Components "Probe `sandbox`").
- **Seccomp filter.** A compiled cBPF program, loaded with `--seccomp`. Every argument rule loads only the low 32 bits of the argument and ignores the high word, as the kernel does for an `int` argument, so a high bit cannot slip a value past a compare (CVE-2019-10063). The program:
  - allows `socket()` only when the domain is `AF_INET`, `AF_INET6` or `AF_NETLINK`, and denies every other family, `AF_UNIX` and `AF_VSOCK` included. So the strain makes no socket that reaches a path socket, an abstract socket or a host vsock service;
  - allows `socketpair()` only when the domain is `AF_UNIX` and the type, with `SOCK_NONBLOCK` and `SOCK_CLOEXEC` masked off, is `SOCK_STREAM` or `SOCK_SEQPACKET`. A connected stream pair reaches nothing outside the pair; a datagram socket could `sendto` any visible socket path, so datagram pairs are denied;
  - denies `io_uring_setup()`, since io_uring can make a socket that seccomp does not see;
  - denies `ioctl()` with `TIOCSTI` or `TIOCLINUX`, so the strain cannot push input into a terminal;
  - kills a call made through any system call ABI other than the native one, such as i386 or x32 calls on x86_64, so the filter cannot be stepped around;
  - allows every other call.

  A fixed script builds the program for x86_64 and aarch64. On any other architecture it refuses, and the launch fails.
- **Terminal.** The launcher does not use `--new-session`, so the interactive TUI keeps its controlling terminal and resize signals. The filter's `TIOCSTI` rule is bubblewrap's documented alternative.
- **WSL2.** `/run/WSL` is absent, `env -i` drops `WSL_INTEROP`, and the filter allows no Unix socket `/init` could use. So a strain cannot start a Windows program.
- **The launch command.** A fixed builder script makes the launcher argv from the spawn record and the Lair's state root (Contracts and seams, "Launcher argv"). The tmux command string holds only fixed literals, the asserted brood id, and paths that are each one double-quoted word behind the charset gate. Its `env -i` words come first and exec bubblewrap, so each credential value travels in the environment, never in bubblewrap's argv.
- **Mounts the strain cannot undo.** Bubblewrap's mounts are locked against a namespace the strain makes inside its sandbox ([mount_namespaces(7)](https://man7.org/linux/man-pages/man7/mount_namespaces.7.html), "Restrictions on mount namespaces"). So a nested namespace cannot unmount the tmpfs over `.claude/worktrees/` to reveal its siblings, or the read-only `objects/info/` bind.

### Linux egress

Built by #604. The relay's implementation is #604's choice under these properties.

- The strain's network namespace holds only loopback. A server the strain starts on loopback is its own, and no other process can reach it.
- Its one way out is a forwarder attached to the strain's network namespace from outside, after the sandbox starts and before its command runs: it joins only the sandbox's user and network namespaces, listens on a fixed loopback port inside them, and relays each connection to the Lair's proxy over the Lair's relay socket. The forwarder stays outside the strain's PID and mount namespaces, so the strain cannot signal it or replace its socket.
- **The attach.** One fixed step of the builder script, `lair-sandbox.sh attach`, does it. `spawn-brood.sh` in Lair mode calls it in Pass 1, right after `tmux new-session` (line 912), and the probe calls it after each probe session starts. A file descriptor cannot pass through `tmux new-session`, so the step uses two FIFOs:
  1. Before `tmux new-session`, the caller makes the FIFOs `info` and `block`, mode 0600, in the per-strain folder, which the strain's view hides. It holds both open read-write, which never blocks on Linux, so the pane's own opens never wait, and the attach step inherits them.
  2. The command string opens them onto bubblewrap's descriptors: `--info-fd 3 --block-fd 4`, with `3>"<info>"` and `4<"<block>"`.
  3. The step reads `child-pid` and the network namespace id from `info`, within a fixed 30-second deadline.
  4. It starts the forwarder, detached, in that process's user and network namespaces, and waits for its ready line within the same deadline.
  5. It writes the forwarder record (State and ownership), removes the third-source token file, and writes one byte to `block`. Bubblewrap then runs the command.
  6. On a passed deadline it kills the session, removes the token file, and the spawn fails (Failure modes).

  The shared ready deadline, `READY_TIMEOUT`, is set at line 1143, after Pass 1, so the attach never spends it.
- The forwarder holds a process handle on the sandbox's child and exits when that process ends.
- The fixed port is a constant of the launcher. It is always free, because every strain's namespace is new.
- The proxy runs outside every sandbox for the Lair session. It accepts HTTP `CONNECT` and plain HTTP requests, resolves each name itself, and checks the address it will connect to after resolution. It refuses loopback, link-local and unspecified addresses, every address of the host's own interfaces and, on WSL2, the Windows host's address. It does not open TLS. It reaches remote hosts through the user's own proxy settings when they are set.
- The strain's proxy variables are literals that name the forwarder (Contracts and seams, "Environment literals"). The namespace has no name resolver, so names resolve only at the proxy.
- A tool that ignores proxy variables cannot connect anywhere but its own loopback. That is a stated property, not a fault: such a tool fails visibly in the strain.
- There is no host allowlist: a strain reaches any remote host through the proxy. That is the egress residual under Trust boundaries.

### GitHub remotes

Built by #604. The strain has no SSH agent socket, so git reaches GitHub over HTTPS with `gh` as its credential helper.

- `GIT_CONFIG_*` literals rewrite `git@<host>:` and `ssh://git@<host>/` to `https://<host>/` with `url.https://<host>/.insteadOf`. `<host>` is the repository's host, which #608 fixes at Lair start (merge lane, "Merge environment", "The host binding"), lowercased, behind the gate `^[a-z0-9.-]+$`.
- They set `credential.helper` first to an empty value, which drops every helper git read before, then to `!gh auth git-credential`. `gh` resolves through `PATH`, whose directories the strain cannot write (I4).
- A remote on another host, or one that answers only over SSH, fails. The preflight's `git_remote` probe catches it (P26 degradation).

### macOS launcher

Built by #604. macOS has no namespaces, so the strain runs under a Seatbelt profile through `sandbox-exec`.

- **The profile.** A fixed script generates it per strain into the per-strain folder, outside the strain's writable folders. Each path in it is one quoted string behind the charset gate. The profile:
  - allows by default, then denies every file write and allows writes only to the allowlist of I5 and to the device files a terminal program needs, such as `/dev/null` and the pane's terminal;
  - denies every read and write under `<state root>/control/`;
  - denies every Unix socket connect, then allows only the name service socket the system resolver needs;
  - denies every TCP connect to loopback (`localhost`);
  - denies every mach service lookup, then allows only a named list: the services Claude Code, `gh`, git and the system resolver need, such as the Keychain, certificate trust, the resolver, notifications, preferences and logging. LaunchServices, Apple Events and every other service outside the list stay denied. A listed service can write files on the strain's behalf, outside the file rules, so each one is checked for such writes (Verification strategy, "Live-probe assumptions");
  - denies `user-preference-write`, so the preferences service writes no preference file for the strain, such as a terminal's startup command; it allows no preference domain;
  - denies sending Apple Events and creating launchd jobs;
  - denies sending a signal to, and reading process information of, any process outside the profile, where the profile language has that operation.
- **Confirmed at each start.** The probe's channel cases `launchd`, `launchservices` and `appleevents` each try to run a command outside the profile, `preferences` tries a preference write, and `loopback` tries a local TCP connect (Components "Probe `sandbox`"). If any of them succeeds or cannot run, the probe fails and the Lair claims nothing on macOS. No macOS strain runs on the basis that an escape is a residual.
- **What remains.** The profile does not hide the Lair's processes, as the 2026-11-22 amendment on process reach states ("the Lair's strains can read its key where no sandbox hides its processes"). A flaw in Seatbelt or the kernel that lets a strain out falls under the 2026-11-21 amendment on forged markers ("a Lair-started session that escapes its containment" can sign markers that count). Both are in Trust boundaries, "Residual: what macOS leaves".
- **No nesting.** A tool inside the strain that starts its own `sandbox-exec` fails. Codex does so, so the `codex-plugin` preset fails in a macOS strain (Consumer degradation). A local review tool that does so fails the preflight's `local_review` probe, which runs inside the sandbox (Components "Probe `sandbox`").
- **No proxy.** A macOS strain reaches remote hosts directly, with the proxy names passed as strain launch lists them. A service bound to one of the host's own non-loopback addresses stays reachable, since the profile denies loopback only; that is in "Residual: what macOS leaves".

### Write allowlist

Built by #604. These are the writable binds on Linux and the allowed write paths on macOS.

- **Own worktree**, `<checkout>/.claude/worktrees/<brood-id>/<short>/`.
- **Own admin folder**, `<common>/worktrees/<name>/`, where git keeps the worktree's `HEAD`, index, `FETCH_HEAD`, `ORIG_HEAD` and `logs/HEAD`.
- **The shared object store** `<common>/objects/`, with `<common>/objects/info/` read-only, so no strain can write an `alternates` file, a commit-graph file or another file there that every git process of the checkout loads.
- **The shared ref store** `<common>/refs/` and `<common>/logs/`. Lair mode runs only on the files ref backend (Lifecycle, "Start"). `<common>/packed-refs` lives in the read-only common directory, so a strain cannot delete a packed ref.
- **The per-strain scratch folder** `<state root>/sandbox/<nonce>/scratch/`, named by `TMPDIR`, with `XDG_CACHE_HOME` at `scratch/cache/`.
- **The per-strain Claude Code state folder** `<state root>/sandbox/<nonce>/claude/`, named by `CLAUDE_CONFIG_DIR`.
- **The per-strain Codex home** `<state root>/sandbox/<nonce>/codex/`, named by `CODEX_HOME` (Components "Claude Code state and auth").

`<nonce>` is the strain record's nonce, strain launch's `lair_nonce`. The Lair creates the per-strain folders, mode 0700, before the spawn, and removes them at clean-up. The per-strain folder itself is not writable to the strain.

Three git settings follow from the read-only common directory:

- `gc.auto=0` and `maintenance.auto=false` are environment literals, so no strain starts a gc or maintenance run on the shared store. The merge lane sets the same pair for its own repository.
- `fetch.prune=false` is a literal, so a fetch never tries to delete a packed remote-tracking ref.
- `core.fsmonitor=false` is a literal, so git starts no monitor daemon, which needs a Unix socket.

Clean-up takes every path from the spawn record, never from the admin folder's `gitdir` file, which a strain can rewrite: the worktree path, and the admin folder name, which Lair-mode `spawn-brood.sh` reads with `git rev-parse --git-dir` right after `git worktree add`, before the session starts. The Lair checks with `lstat` that each path is a directory, not a link, removes it, then runs `git worktree prune` in its own checkout, never `git worktree remove`, whose clean check runs `git status` inside the worktree (Requirement I4).

### Claude Code state and auth

Built by #604.

- `CLAUDE_CONFIG_DIR` names the per-strain Claude Code state folder. Before the spawn the Lair fills it with:
  - read-only views of the user's Claude Code settings file, memory file, `plugins/`, and user-level agents, commands and skills: read-only binds on Linux; links on macOS, whose targets the profile keeps read-only;
  - a copy of the user's `~/.claude.json`, so the strain starts with the user's onboarding and trust state and writes only its copy.
- No strain writes the user's Claude Code settings, plugin folder, `~/.claude.json` or credential store.
- **Auth needs no write to the user's store.** An OAuth refresh made from a copied refresh token rotates the user's own token away, whether or not the copy is written back. So on Linux a strain authenticates only with `CLAUDE_CODE_OAUTH_TOKEN` or `ANTHROPIC_API_KEY` from the tmux server's environment. The Lair never copies or binds `~/.claude/.credentials.json`.
- On macOS the strain reads the user's Keychain item through the Keychain service. The profile cannot split Keychain reads from writes, so a refresh updates the user's own item in place, as any of the user's sessions does. No copy exists, so no token is rotated away. Requirement I6 allows this reach.
- When no source works, the `claude-start` case fails, with its fix (Consumer degradation).
- **Codex home.** Codex, the default local review tool, writes its home folder, which a strain cannot write under the user's `$HOME`. So `CODEX_HOME` names the per-strain Codex home on both platforms. Before the spawn the Lair puts there a copy of the user's Codex `config.toml`, from the user's `CODEX_HOME` or `~/.codex/`. It never copies or binds `auth.json`, for the same reason as Claude Code's credential file: a refresh from a copied token rotates the user's token away. So Codex in a strain authenticates only with `OPENAI_API_KEY` from the tmux server's environment. When that fails, or Codex cannot run inside the sandbox, the `local_review` probe fails, with its fix (Consumer degradation).

### Keyring and session bus

Built by #604. This answers integration R3-3.

- On Linux the strain reaches no session bus: `DBUS_SESSION_BUS_ADDRESS` is not passed, its usual socket sits under `$XDG_RUNTIME_DIR`, a fresh tmpfs in the view, and the filter allows no Unix socket but a connected pair. So the Secret Service keyring is out of reach, and `gh` and git's libsecret helper lose a token stored there.
- The strain's GitHub credentials come from the first source that works, in this order:
  1. `GH_TOKEN` or `GITHUB_TOKEN`, already set in the tmux server's environment, passed as strain launch lists them;
  2. `gh`'s plain-file storage, `hosts.yml` in its config folder, which the strain reads read-only;
  3. otherwise the Lair runs `gh auth token` outside the sandbox at each spawn and writes the result to the token file `gh-token`, mode 0600, in the per-strain folder, which the strain's view hides. The command string's first statement reads that file into `GH_TOKEN` in the pane shell, and its `exec env -i` statement passes it with strain launch's `${GH_TOKEN+...}` word. The attach step removes the file before it unblocks the sandbox. No `tmux -e` is used, and the value is never in the command string or any tmux argv.
- No credential value is in the argv of a long-lived process: not tmux's, bubblewrap's, the forwarder's or `claude`'s. Another local account could read such an argv through `/proc/<pid>/cmdline` on a host without `hidepid`. A value is in `env`'s own argv until `env` execs bubblewrap, its first act; that is the residual "a credential in `env`'s argv".
- Git reaches the same credentials through `gh auth git-credential` (Components "GitHub remotes").
- These are still the user's own credentials (ADR-0045 decision 9). No source widens what a strain can do on GitHub.
- When none works, the `gh_auth` probe fails, with its fix (Consumer degradation).
- On macOS the Keychain stays reachable, so `gh` works as it does for the user. The fallback order is Linux only.

### Probe `sandbox`

Built by #608, with #604's launcher; #604's live probe runs the same cases by hand. This answers integration R1-5 and R3-4.

**When.** At each Lair start, before any claim, as part of strain launch's environment preflight, which now runs inside the sandbox. It reuses the preflight's clean start, run nonce and 900-second deadline.

**Scratch targets, fresh nonces, real locations.** The probe draws a fresh nonce `N`, 32 lowercase hex digits. Every target is a scratch item named for `N`, made by the Lair outside every sandbox, in the real location a strain's or the Lair's own item would have. The probe never touches the real key, the halt file, the lock, a kept worktree or a live strain's folders. Each probe session gets a full strain layout from the same builder a strain uses: a detached scratch worktree at `<checkout>/.claude/worktrees/lair-probe-<N>/<x>/`, its admin folder, per-strain folders at `<state root>/sandbox/probe-<N>-<x>/`, and a record folder at `.hivemind/lair/strains/probe-<N>-<x>/` holding a `spawn.json`, with `<x>` one of `a`, `b` or `l`. A `probe-` name can never be read as a claim nonce.

**Launch order.** Each session starts on the default tmux server, named with `-L default` (Components "The Lair's tmux server"). On Linux the Lair runs the attach step right after each session starts (Components "Linux egress").

1. Clean start. The Lair removes every leftover of an earlier probe by its fixed name patterns, as clean-up removes a strain's folders: `lstat` shows a directory, not a link, it is removed, then `git worktree prune` runs in the Lair's checkout. It then makes the targets of the cases below and layout `a`.
2. Session `a` starts in the sandbox. It is strain launch's preflight session: it runs #608's probe script, which runs `gh_auth`, `git_remote` and `local_review`, then the `sandbox` cases.
3. The Lair makes layout `b`, a sibling created after `a` started.
4. Session `b` starts in the sandbox and runs the `sandbox` cases only.
5. The Lair makes layout `l`, the late sibling neither session saw at its start.
6. The Lair writes a go file, holding `N` and the Lair's own process id, into each session's scratch folder. Each session runs its cases only after it reads the go file.
7. Each session writes its result file, `N` and each case's id and outcome, to its own scratch folder. The preflight's result file moves there from `.hivemind/lair/preflight/`, which is read-only in the sandbox.
8. After both sessions end, the Lair checks every target from outside: each scratch file unchanged, each forbidden new file absent, each witness file absent, and the common directory's `config` byte-equal to its copy from before step 2.
9. The Lair starts `claude` with a strain's arguments in layout `a`, as the case `claude-start`, then ends it.
10. The Lair removes every scratch item.

**Cases.** "L" is Linux, WSL2 included; "M" is macOS. A session runs only its platform's cases. An escape case passes only when every attempt fails and the Lair's own check in step 8 finds no change. No pass rests on the exit status alone of an attempt against a real service, one the Lair did not make, since a reached service can also fail a command: such an attempt that would run a command outside the sandbox if it got through creates a witness the Lair checks, and an attempt that only asks a service has a positive control, a Lair call outside the sandbox showing that the service answers it; a control that fails makes the case one that cannot run.

### Concurrency gate

Built by #612.

- The Lair runs more than one strain at once only on Linux, and only when this Lair session's probe `sandbox` passed every case, the `sibling` cases included.
- On macOS it always runs one strain or remediation strain at a time.
- A failed probe stops the Lair before any claim, so it runs no strain at all.

### The Lair's tmux server

Built by #608, with #604 for `spawn-brood.sh`. The Lair's own window runs on its own tmux server, on `control/lair.sock`, as answer 1A states. The strains stay on the default server, where `brood-status` and the user find them. So no strain shares a server, or a server's global environment, with the Lair. The user attaches with `tmux -S <path> attach`. Start checks the socket's path length, as for `control/scan.sock`.

Without `lair_nonce`, `spawn-brood.sh`'s calls are unchanged.

## Contracts and seams

Fields and seams only. Each slice builds the code.

- **Launcher argv.** One fixed builder script, `plugin/skills/spawn-brood/scripts/lair-sandbox.sh`, makes the bubblewrap argv on Linux and the Seatbelt profile on macOS. Its inputs are the spawn record, the state root, the repository's host, `PATH` and the user's config paths. Each path is one double-quoted word behind the charset gate of `spawn-brood.sh`'s plugin read rule: absolute, with bytes only in `[A-Za-z0-9 ._/@+()-]`. A path that fails the gate refuses the launch, a bound `PATH` directory or link target folder included. It prints one fixed reason on any refusal.
  - **Overlap rule.** The builder refuses when a writable bind and a named I4 leaf path are equal, or one lies inside the other. The named leaf paths are those I4 names, with the user's whole Claude Code folder. A relative or empty `PATH` entry also refuses, since it names the worktree. Exactly two overlaps are allowed, both of the real layout: the own worktree bind at `<checkout>/.claude/worktrees/<brood-id>/<short>/`, inside the main checkout's `.claude/`; and `<common>/objects/info/` inside the `<common>/objects/` bind, with its read-only bind after it.
  - **Wide-bind rule.** The builder refuses, with reason `bind-wide`, a read-only bind whose resolved source equals the resolved form, by `realpath`, of `/`, `$HOME`, the state root or the user's Claude Code folder, or contains one of them, a `PATH` directory or link target folder included. So a link `~/.local/bin/x -> ~/x` refuses the launch rather than binding `$HOME`. On WSL2 a `PATH` entry under a Windows drive mount, such as `/mnt/c/`, is dropped from the bound list, never bound; and a link to WSL's `/init`, such as `wslpath`, is not followed, so `/init`'s folder `/` is never bound and the link fails in the strain.
  - **Command order.** `spawn-brood.sh` in Lair mode builds the command string as: on Linux under the third credential source, the token file read; then `exec env -i <words>`; then the builder's words; then `claude ...`. So `env -i` execs bubblewrap, or `sandbox-exec`, with each value in its environment. On Linux the string ends with the attach FIFO redirections. Without `lair_nonce` nothing changes.
- **Environment literals.** These change strain launch's Contract "Strain environment":
  - no longer passed: `SSH_AUTH_SOCK` and `DBUS_SESSION_BUS_ADDRESS`;
  - set by the Lair as literals, on both platforms: `TMPDIR`, `XDG_CACHE_HOME`, `CLAUDE_CONFIG_DIR` and `CODEX_HOME` to the per-strain folders; and `GIT_CONFIG_COUNT` with these key and value pairs, in order: `credential.helper` empty; `credential.helper` `!gh auth git-credential`; `url.https://<host>/.insteadOf` `git@<host>:`; `url.https://<host>/.insteadOf` `ssh://git@<host>/`; `gc.auto` `0`; `maintenance.auto` `false`; `fetch.prune` `false`; `core.fsmonitor` `false`;
  - set as literals on Linux only: `HTTPS_PROXY`, `HTTP_PROXY`, `https_proxy` and `http_proxy` to `http://127.0.0.1:<port>`, and `NO_PROXY` and `no_proxy` to `localhost,127.0.0.1,::1`;
  - every other name stays as strain launch lists it. A name the live probe finds missing is added by a dated amendment, never by a wildcard.
- **Strain settings.** The fragment gains `"sandbox": {"enabled": false}`. The outer sandbox holds the whole session, and Claude Code's own sandbox cannot start inside it, since it needs a Unix socket relay. A managed setting sits above `--settings`, so a managed `sandbox.enabled` still wins (Consumer degradation).
- **Seam with strain launch, the preflight.** The preflight session runs inside the sandbox, as session `a` of the probe `sandbox`, in a strain layout at a strain worktree location, instead of a scratch worktree in `.hivemind/lair/preflight/`. The probe script takes a second argument, its session's scratch folder, where it writes its result. The preflight folder keeps the reviewer setting and the run nonce, read-only to the session. The stop cause adds the case id for probe `sandbox`.
- **Seam with strain launch, tmux.** In Lair mode every tmux call of `spawn-brood.sh` and of the Lair names `-L default` (Components "The Lair's tmux server").
- **Seam with strain launch, clean-up.** Lifecycle step 5's head check names no path of the strain's layout in any git or `gh` call (Lifecycle, "Clean-up"). A kept worktree is strain-written, so it is never opened in place: the rescue step, in the queue report and in the Failure modes row "Unpushed work at session end", names only a push from the main checkout, `git push <remote> <head>:refs/heads/<branch>`, and drops the option to delete `.hivemind/lair/launch.json`.
- **Seam with strain launch, the Lair-mode scripts.** In Lair mode `push-branch.sh` records no upstream: its push names its expected commit and never reads the upstream, and the shared config is read-only in the sandbox. In Lair mode `create-working-branch.sh` changes no upstream, for the same reason. Without a verified marker both scripts behave as today.
- **Seam with strain launch, the spawn record.** `spawn.json` gains `admin`, the admin folder name (State and ownership).
- **Seam with claim integrity.** Its "Assumptions about #630":
  - "Containment of the key and the halt file" and "Tmux reach": met on Linux by I1 and I2; on macOS by the profile, confirmed by the probe's channel cases, with what remains under the 2026-11-21 amendment on forged markers and the 2026-11-22 amendment on process reach (Trust boundaries, "Residual: what macOS leaves");
  - "Process reach": met on Linux by the PID namespace and the fresh `/proc`; on macOS the profile denies signals and process information where its language has those operations, and what remains is under both amendments, as above;
  - "Result file per strain": met on Linux by I3. On macOS the profile denies a strain every sibling's files, and strains run one at a time, so no sibling runs beside it; a kept worktree is still write-denied. What remains is under both amendments, as above.
- **Seam with the merge lane.** Its assumption that "a strain writes nothing outside its worktree and the shared object and ref store" is met on Linux by I4 and I5, and on macOS by the profile, with "Residual: what macOS leaves". Its residual "a strain that writes the tick's inputs" narrows to a strain that escapes containment. Its cache, under `control/`, is covered by I1. Its "Git and tool reads" gain that, once a strain's session has started, no Lair git or `gh` call has a path of its layout as its working folder, in an argument or in its environment (I4), and that the clean-up head check resolves no strain branch against the shared ref store, which it reads only as data before it tests ancestry in the Lair's own bare repository (Lifecycle, "Clean-up").
- **Seam with #608.** #608 builds the probe `sandbox`, the relay and proxy, the forwarder's per-tick check, the Lair's tmux server, the Start checks of the new socket paths, the Start refusal of a ref backend other than `files` with failure code `ref-backend-unsupported`, the clean-up head check, the unlink of a kept worktree's non-regular admin-folder entries, and the child timeout on the probe's and clean-up's `git worktree prune`.
- **Seam with #612.** #612 builds the concurrency gate.
- **Seam with #611.** `control/digest/` is under `control/`, so I1 covers it.

## Trust boundaries

A strain is untrusted after spawn (strain launch, Trust boundaries, "Strain containment"). This design narrows what it can reach. It changes no channel through which the user steers the Lair.

**On Linux.** The strain reaches only what Requirement allows. Its reads cover only the named binds of its view; the state root, `$HOME` and the runtime folders are absent. Its writes are the allowlist. It makes no Unix socket but a connected stream pair. It reaches remote hosts only through the proxy, and sees and signals only its own processes. So the key, the halt file, the tmux servers, every user service, every sibling's files and every shared run-or-load file are out of reach. Strain launch's "Named residual: the tmux global environment" holds only for a strain that escapes containment.

**On macOS.** The profile holds the strain to I1 to I5, confirmed at each start by the probe, the channel cases included. `launchd`, LaunchServices and Apple Events are denied, not left as a way out.

These residuals remain, each with its ground and bounded impact.

- **Residual: what macOS leaves.**
  - Scope: a strain that reads the key out of the Lair's processes, which the profile does not hide; a strain that gets out through a flaw in Seatbelt or the kernel; and a local service bound to one of the host's own non-loopback addresses.
  - Ground: the ADR-0045 amendment of 2026-11-22, "the Lair's strains can read its key where no sandbox hides its processes", for process reach; and the ADR-0045 amendment of 2026-11-21, "sessions running as the user can forge Lair markers", for an escape from containment. The user accepted both. A service on a non-loopback address is open to the network already.
  - Bounded impact: what those two amendments state, a forged marker that counts, plus what ADR-0045's residual "A prompt-injected strain holds the user's rights" states. A service on a non-loopback address gives a strain only what any host on that network gets. On macOS strains run one at a time, so no sibling runs beside an escaped strain. Merges still pass `merge-approved.sh`'s gates, and a merge is reverted (ADR-0045 decision 14).
- **Residual: a special file or mount made after the launch.**
  - Scope: on Linux, a FIFO or a mount that root, or the user's own processes outside the Lair, make under a bound path while a strain runs; under a system directory only root can. The strain can write into such a FIFO, since a FIFO write does not write its file system ([fifo(7)](https://man7.org/linux/man-pages/man7/fifo.7.html)), and the mount appears with its own flags, since bubblewrap's mounts are slaves (Context and code truth).
  - Ground: the threat this design contains is the strain, untrusted after spawn (strain launch, Trust boundaries, "Strain containment"). Root and the user's own processes are outside it and already read the key, "a file only the user's account can read" (ADR-0045 amendment of 2026-11-21). The strain mounts nothing on the host, and a FIFO it makes lies in an I5 folder.
  - Bounded impact: what that FIFO's reader does with the bytes, or the strain's writes to that file system with the user's rights. A reader that runs commands from the bytes is an escape, bounded as for "a kernel or sandbox bug": a forged marker that counts, under the ADR-0045 amendment of 2026-11-21, plus ADR-0045's residual "A prompt-injected strain holds the user's rights". The next start's `special-files` and `read-only` cases check the whole view again.
- **Residual: a credential in `env`'s argv.**
  - Scope: each credential value strain launch passes is an `env -i` word, so it is in `env`'s argv until `env` execs bubblewrap or `sandbox-exec`.
  - Ground: strain launch's Contract "Strain environment", which passes values as `env -i` words. The pin of Verification strategy keeps every value out of every long-lived process's argv.
  - Bounded impact: another local account reads a value only by catching `env` in that instant, and on Linux only on a host without `hidepid`. The value is the user's own token, as ADR-0045 decision 9 states.
- **Residual: the shared object and ref store.**
  - Scope: a strain writes the shared object and ref store, which worktree strains must (ADR-0017 decisions 1 and 2). So it can move other worktrees' local refs, its siblings' branches and remote-tracking refs included, add `refs/replace/` refs, and delete or corrupt packs. It can also make a FIFO at a loose ref, `<common>/refs/heads/<branch>`, which stalls a git process that reads that ref, or at its own admin folder's `HEAD`, `gitdir` or `commondir`, which stalls every `git worktree add` and `git worktree prune` in the checkout, since git reads every admin folder.
  - Ground: the worktree model of ADR-0017 and strain launch. The other option, a per-strain clone, is rejected under Decisions.
  - Bounded impact:
    - a moved remote branch needs a push, and every strain push is leased to its own expected commit (strain launch, Components "Start points");
    - a sibling that builds on a moved ref pushes that content into its own pull request's diff, where the merge lane's gates, local review and the auto-tier checks read it, and the merge lane's result checks bind `pr`, `branch` and `head` to GitHub;
    - the Lair's own git reads use its own repository under `control/`, with replace objects off (merge lane, "Git and tool reads");
    - deleted objects are denial of service: a run fails, and pushed work is on the remote. The user's unpushed work in the main checkout shares the store and can be lost or rewritten;
    - a FIFO at a loose ref, or at an admin folder's `HEAD`, `gitdir` or `commondir`, is denial of service: the clean-up head check runs no git against the shared ref store, and its helper's non-blocking open and its check on that same descriptor refuse the FIFO and keep the worktree (Lifecycle, "Clean-up"); every Lair git call in its checkout runs under the child timeout, so a stalled one is killed and fails the spawn or clean-up visibly; a sibling's or the user's own git process in the main checkout stalls until it is ended and writes nothing. Clean-up unlinks a FIFO at a kept worktree's admin-folder `HEAD`, `gitdir` or `commondir`. A FIFO at a loose ref stays until the user removes it, and stalls each later git call that reads every ref.

    This sits inside ADR-0045's residual "A prompt-injected strain holds the user's rights", which already lets a strain move or delete branches on the remote with the user's credentials.
- **Residual: network egress with the user's credentials.**
  - Scope: a strain reaches any remote host through the proxy, holding the user's GitHub token and its Claude credentials, so it can send what it reads to any host.
  - Ground: ADR-0045 decision 9, everything runs under the user's credentials, and its residual "A prompt-injected strain holds the user's rights". The Lair's settings fragment turns off Claude Code's own sandbox, so a user's Bash host allowlist does not apply in a Lair strain.
  - Bounded impact: what the user's GitHub and Claude accounts can do. The proxy keeps the strain off local services, the host and, on WSL2, the Windows host. A dedicated identity (ADR-0045 decision 9, deferred) is the real fix.
- **Residual: a kernel or sandbox bug.**
  - Scope: a flaw in the kernel's namespaces, mounts or seccomp, in bubblewrap, or in Seatbelt, that lets a strain out.
  - Ground: the platform is the boundary; the plugin ships no kernel code.
  - Bounded impact: what the ADR-0045 amendment of 2026-11-21 states for an escape, a forged marker that counts, plus ADR-0045's residual "A prompt-injected strain holds the user's rights". Merges still pass `merge-approved.sh`'s gates. The probe `sandbox` checks the properties at each start, not the absence of flaws.

## Lifecycle

1. **Start.** Claim integrity's Start runs, with the socket path checks of State and ownership. Before any strain starts, the Lair reads `extensions.refStorage` from the main checkout's config and refuses Lair mode with failure code `ref-backend-unsupported` when it is set to anything but `files`, since the head check reads only the files backend (Consumer degradation). The Lair starts its proxy on `relay.sock` (Linux) and its window on `control/lair.sock`.
2. **Probe.** The environment preflight runs inside the sandbox, with the probe `sandbox`. Any failure stops the Lair before its first claim.
3. **Claims.** Admission and the claim run as claim integrity states. #612's gate decides whether a second strain may start.
4. **Spawn.** After strain launch's writes, the Lair creates the per-strain folders, the Claude Code state views, the `~/.claude.json` copy and the Codex `config.toml` copy, and, on Linux under the third credential source, writes the token file. `spawn-brood.sh` in Lair mode creates the worktree, records `admin` in `spawn.json`, builds the launcher argv or profile, makes the attach FIFOs on Linux, and starts the session on the default server. On Linux it then runs the attach step in Pass 1, and the sandbox command runs once the forwarder is attached. Spawn's own steps run outside the sandbox; everything the pane runs after `exec env -i` runs inside it.
5. **Run.** As strain launch states, inside the sandbox.
6. **End.** The Lair ends the session as strain launch states. `--die-with-parent` ends the sandbox with the pane. The forwarder exits when the sandbox's process ends; if its record still matches a live process, the Lair kills it.
7. **Clean-up.** As strain launch's Lifecycle step 5 and the parent design's Seams item 7 state, with this head check. No Lair git or `gh` call names a path of the strain's layout (Requirement I4), and the head check runs no git against the shared ref store, which strains write. One fixed `perl` helper, already required at Start, reads each file as data under the child timeout (merge lane, "Merge-lane step of the tick"): one `sysopen` with `O_RDONLY|O_NOFOLLOW|O_NONBLOCK`, then `stat` on that same handle, which must show a regular file under the cap, then a bounded read from that handle. So a swap after the open cannot change what is read, and a FIFO never blocks. It reads `<common>/worktrees/<admin>/HEAD`, cap 4096 bytes, holding exactly a commit id or `ref: refs/heads/<branch>`, with a name `git check-ref-format` accepts as `refs/heads/<branch>` in the Lair's own bare repository. For a branch it reads the loose ref `<common>/refs/heads/<branch>`, cap 4096 bytes, holding exactly a commit id; when that is absent, `<common>/packed-refs`, cap 16 MiB, in which exactly one line names the ref, as `<id> refs/heads/<branch>`. The parsed commit id must match `^[0-9a-f]{40}$|^[0-9a-f]{64}$`. Ancestry is tested only in the Lair's own bare repository (merge lane, "Git and tool reads"): the head counts as on the remote only when it, after fetching the branch, finds the head an ancestor of the fetched head. Any failure keeps the worktree: a link, a FIFO or other non-regular file, a file over its cap, a bad form, a missing object, a killed helper or any failed read. Every Lair git call in its own checkout, `spawn-brood.sh`'s `git worktree add` and `git rev-parse --git-dir` in Lair mode and every `git worktree prune` included, runs under the same child timeout, since a FIFO a strain leaves at an admin folder's `HEAD` or `gitdir`, or at a loose ref, stalls git; a killed call fails the spawn or the clean-up visibly. #604 wraps `spawn-brood.sh`'s two calls with the timeout tool claim integrity's Start step 1 resolves, at the same 300 seconds and 10-second kill grace, since #604 is built before #605's child timeout. When the worktree is removed, the Lair also removes the admin folder and the per-strain folder, taking each path from the spawn record (Components "Write allowlist"). A kept worktree keeps its per-strain folder, less its token file. For a kept worktree the Lair also `lstat`s its admin folder's `HEAD`, `gitdir` and `commondir`, opening none of them, and unlinks by name each that is not a regular file, naming its path in the queue report, so a FIFO a strain left there does not stall every later `git worktree add` and `git worktree prune`. The worktree's files stay.
8. **Stop.** The Lair stops its proxy and removes `relay.sock`.

## Decisions

A decision that is not ADR-worthy names the [P20](../../engineering-principles.md) condition it fails. Every decision below was taken by the run under `plugin/governance/decision-autonomy.md` (Tier B — Auto-Decide and Journal), each with a strong recommendation, and is listed for veto.

- **An outer sandbox wraps the whole strain command; Claude Code's own `sandbox` setting is not used.** That setting covers shell commands only, not the file tools, hooks or MCP servers. Not ADR-worthy: fails P20's hard-to-reverse condition.
- **Linux uses bubblewrap with user, PID, IPC, UTS and network namespaces, a deny-by-default view and the I5 allowlist.** The other option, Landlock, needs Linux 6.12 for its abstract socket scope, newer than many hosts run, and does not hide processes. Not ADR-worthy: fails P20's hard-to-reverse condition.
- **Socket families are an allowlist in a seccomp filter: `socket()` makes only `AF_INET`, `AF_INET6` and `AF_NETLINK` sockets, and `socketpair()` only Unix stream and seqpacket pairs, with every argument compared on its low 32 bits. So I2 holds by construction.** The other option, hiding socket paths with tmpfs folders, is a list of known places: a socket under `$HOME`, where any tool may create one, would stay reachable (integration R3-2). A denylist of `AF_UNIX` alone left datagram pairs and `AF_VSOCK`. The cost: a project whose build or tests create a Unix socket fails under the Lair. Not ADR-worthy: fails P20's hard-to-reverse condition.
- **The Linux view is deny by default: a read-only tmpfs root with named read-only binds, the I5 writable binds and private tmpfs folders, checked at each start by the `read-only` and `special-files` cases.** The other option, a read-only bind of the whole root, showed every host FIFO, which a read-only mount does not stop, and every mount made later anywhere on the host, which bubblewrap's slave mounts receive. The cost: a tool that needs a path outside the binds fails visibly (Consumer degradation). Not ADR-worthy: fails P20's hard-to-reverse condition.
- **The attach step lives in `lair-sandbox.sh`, run by `spawn-brood.sh` in Pass 1 and by the probe, through two FIFOs in the per-strain folder.** A descriptor cannot pass through `tmux new-session`, and Pass 1 ends before the shared ready deadline starts. Not ADR-worthy: fails P20's hard-to-reverse condition.
- **In Lair mode every tmux call names `-L default`.** The Lair window's `$TMUX` would send a bare call to the Lair's own server. The other option, unsetting `TMUX` for each call, leaves a call that forgets it on the wrong server. Not ADR-worthy: fails P20's hard-to-reverse condition.
- **No Lair git or `gh` call names a path of a strain's or probe's layout once its session starts; the head check reads `HEAD` as data.** The strain writes the files git loads from there. Not ADR-worthy: fails P20's hard-to-reverse condition.
- **The relay's forwarder is attached from outside the strain's namespaces.** The other option, a forwarder inside the sandbox, needs a Unix socket inside it, which the filter denies. Not ADR-worthy: fails P20's hard-to-reverse condition.
- **The filter blocks `TIOCSTI` and `TIOCLINUX`, and the launcher does not use `--new-session`.** The other option, `--new-session`, takes the TUI's controlling terminal, so resize signals stop. Not ADR-worthy: fails P20's hard-to-reverse condition.
- **Egress goes only through a proxy that refuses local addresses, with no host allowlist.** The other option, a host allowlist, would need every host a project's build fetches from. The cost is the egress residual. Not ADR-worthy: fails P20's hard-to-reverse condition.
- **GitHub SSH remotes are rewritten to HTTPS, with `gh` as the only credential helper, and no SSH agent reaches a strain.** An agent socket would let a strain authenticate as the user to any SSH host. Not ADR-worthy: fails P20's hard-to-reverse condition.
- **Strains keep the worktree model and write the shared object and ref store; `objects/info/` is read-only.** The other option, a per-strain clone that borrows objects read-only, would close the store residual but changes ADR-0017's worktree model, `spawn-brood.sh`'s layout, strain launch's Lair checkout rule and `brood-status`. Not ADR-worthy: fails P20's hard-to-reverse condition.
- **Lair-mode `push-branch.sh` records no upstream, and Lair-mode `create-working-branch.sh` changes none.** The shared config is read-only, and Lair mode never reads the upstream. Not ADR-worthy: fails P20's hard-to-reverse condition.
- **Clean-up takes paths only from the spawn record, which gains the admin folder name.** The admin folder is strain-writable. Not ADR-worthy: fails P20's hard-to-reverse condition.
- **A per-strain Claude Code state folder with read-only views; on Linux, auth only by an environment token.** A refresh from a copied token rotates the user's token away. The cost: a Linux user who signed in only by the browser must make a token with `claude setup-token`. Not ADR-worthy: fails P20's hard-to-reverse condition.
- **The keyring fallback order ends with `gh auth token` at spawn, passed through a mode-0600 token file the pane shell reads, and the `env -i` words come before bubblewrap's.** No credential value is in a long-lived argv, and no `tmux -e` is needed, so tmux 3.0a still works. Still the user's own credentials (ADR-0045 decision 9). Not ADR-worthy: fails P20's hard-to-reverse condition.
- **Codex gets a per-strain Codex home with a copy of its `config.toml` and no `auth.json`; it authenticates with `OPENAI_API_KEY`.** Codex writes its home, which a strain cannot write under `$HOME`, and a copied refresh token would rotate the user's away. The other option, a preflight-accepted opt-out to `lair:review`, would change strain launch's probe pass rule and `run-review.sh`'s settings. The cost: with the Codex plugin installed, the Lair runs on macOS only with an argv reviewer setting, and on Linux only with an API key or such a setting. Not ADR-worthy: fails P20's hard-to-reverse condition.
- **The fragment turns off Claude Code's own sandbox in Lair strains.** It cannot start inside the outer sandbox, and the outer one is stricter except for a Bash host allowlist. The cost is named in the egress residual. Not ADR-worthy: fails P20's hard-to-reverse condition.
- **The probe runs at each start, on scratch targets in real locations, with two sessions and a late sibling layout, and a case that cannot run fails it.** The other option, targets in a private folder, could pass where a real location would fail. The cost: three scratch worktrees and two sandbox starts at each Lair start, and one real local review call, as strain launch's preflight already makes. Not ADR-worthy: fails P20's hard-to-reverse condition.
- **macOS runs one strain at a time, under a profile that denies mach lookups by default, preference writes, Apple Events, launchd jobs and loopback TCP, and runs only after the channel cases pass at each start.** A known way out is denied, never accepted as a residual; what remains falls under both ADR-0045 amendments. So PRD user story line 37, several issues at once, is met on Linux only. That is a P26 degradation with a stated fallback, and the PRD's Parallelism criterion, line 79, is conditional on more than one strain running. Not ADR-worthy: fails P20's hard-to-reverse condition.
- **The Lair's window runs on its own tmux server on `control/lair.sock`; strains stay on the default server.** Answer 1A. Not ADR-worthy: fails P20's hard-to-reverse condition.
- **The PRD and ADR-0045 need no change.** ADR-0045's two amendments already state the Linux sandbox and what macOS leaves, which this design builds and relies on.
