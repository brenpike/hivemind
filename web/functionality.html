01 Install

Install inside Claude Code

Run these two commands inside an active Claude Code session. Then run /hivemind:seed-hive once in each project (see Per-project setup).

01 Add the marketplace

/plugin marketplace add https://github.com/brenpike/hivemind.git

02 Install the plugin

/plugin install hivemind@brenpike

02 Requirements

Requirements

bash

macOS, Linux, or WSL on Windows. PowerShell and native Windows are not supported. All toolchain scripts are bash-based.

Shell

git + gh

Git for version control and the GitHub CLI (gh) for PR creation, review automation, and branch management.

Version control

Claude Code CLI

Hivemind is a Claude Code plugin. The Claude Code CLI is the runtime host, so plugins are installed and invoked through it.

Host

jq

Required by the run-ledger engines (hivemind:init-run-ledger, hivemind:record-state-result), by the facts and git scripts (hivemind:gather-facts, hivemind:molt, hivemind:open-plan-pr), and by hivemind:seed-hive.

JSON

When Claude Code's Workflow tool is available, analysis and delivery requests run as workflow scripts; otherwise they run on the workflow state machine (see Lifecycle). tmux is needed only for brood mode. Each strain runs in its own detached tmux session. node is needed only for the optional local Codex review (the codex companion).

03 Per-project setup

Per-project setup

1. Enable in .claude/settings.json

Add two keys to your project's .claude/settings.json. The agent key sets the overlord as the session default. Without it, Claude Code starts with the default agent and the overlord is only reachable on-demand, which bypasses the workflow guarantees.

{
  "enabledPlugins": {
    "hivemind@brenpike": true
  },
  "agent": "hivemind:overlord"
}

Or run the one-shot setup skill:

/hivemind:seed-hive
  • Writes the enabledPlugins and agent keys into .claude/settings.json
  • Gitignores .hivemind/ and .claude/worktrees/
  • Detects companion plugins (caveman, claude-mem, codex) and asks once, in one consolidated confirmation; headless runs auto-enable detected companions
  • Seeds a least-privilege permission allowlist, on by default (see 1a)
  • Invokes hivemind:creep-spread to generate your domain glossary (CONTEXT.md)
  • Records the detected test command under ## Validation in CLAUDE.md when it is absent

.hivemind/ is runtime state created by the overlord and its skills, and is gitignored so it is never committed. It holds the run ledgers (.hivemind/runs/<run-id>/state.json, one per state-machine run; workflow-script runs keep no run ledger), the branch facts files hivemind:gather-facts writes under .hivemind/facts/, brood manifests, the local reviewer's finding ledger, handoffs and the plans they point at, and short-lived inputs files that skills pass to their engine scripts.

1a. Least-privilege permission allowlist (on by default)

seed_allowlist is on by default: seed-hive merges a recommended set of permissions.allow entries: read and output helper Bash commands like echo, grep, jq, and scoped git read subcommands. The Skill(hivemind:route-workflow) entry stops the permission prompt on the read-only routing call the overlord makes for each request. Next to it sit the inputs-file rules, each an Edit(.hivemind/...) entry for one fixed path a skill writes with the Write tool for its engine script, such as Edit(.hivemind/molt-inputs-*.json) and Edit(.hivemind/pr-inputs-*.json). Each one only stops the Write prompt for its path. No Workflow(...) rule is seeded: the workflow approval prompt's don't-ask-again choice is the per-project opt-in. Entries are appended-if-absent; existing entries are never overwritten or removed. After upgrading the plugin, re-run /hivemind:seed-hive to merge any newer entries. To skip the allowlist:

/hivemind:seed-hive seed_allowlist=no

The supported setup for local Codex review is a per-contributor grant: add your Codex cache path to the gitignored .claude/settings.local.json:

"Bash(node /path/to/.claude/plugins/cache/openai-codex/codex/*)"

Replace /path/to/ with your actual home directory path. The codex/* wildcard covers all Codex CLI entry points so the entry does not need updating when Codex is upgraded.

Skill grants are scoped too. While a skill runs, for the rest of that turn and for workflow agents started in it, its allowed-tools pre-approve only the Write of its own inputs file (for example Edit(.hivemind/molt-inputs-*.json) in hivemind:molt) and Reads of plugin files under ~/.claude/plugins/cache/brenpike/hivemind/, a rule that also covers Grep searches of them, per the Claude Code permissions docs and a headless test on Claude Code 2.1.310. Apart from the six user-invoked executor skills (tdd, refactor-to-depth, plan-to-prd, plan-interrogation, create-handoff and creep-spread), which still carry broad Read, Write and Edit, no skill pre-approves a Read or Write of any other path. If the plugin loads from a local path (--plugin-dir, or a marketplace added from a local folder), Reads of its files outside the project prompt; to pre-approve them, add Read(//<absolute plugin folder>/**) to the project's gitignored .claude/settings.local.json. The seeded rules are unchanged.

See the README setup section for the full rationale and the upgrade path for already-seeded projects.

04 Agents

Agents

Four bioforms plus two reviewer agents. Each owns a distinct role. Agents are addressed as hivemind:<agent>.

Agent Role What it does
hivemind:overlord Orchestrator Session default agent and your main interface. Routes each request to a workflow, then launches its workflow script or runs the workflow state machine and its run ledger. Owns branches, checkpoint commits, version-bump decisions, PRs, and review routing. Delegates all implementation and never writes code.
hivemind:cerebrate Strategist Research and implementation planning. Returns the directive: STEP-NNN steps with exact file scopes, dependencies, risks, and a delivery shape (single, multi, or brood). Has no shell: its tools are Read, Glob, Grep, LSP, the web tools, and the claude-mem search tools. Takes branch state only from the facts file. Never writes files.
hivemind:drone Builder Implements code, fixes bugs, refactors, and updates tests and release metadata within explicitly assigned file scope. Default owner of every step. Inside workflow scripts, it also runs the facts and git steps.
hivemind:changeling Shaper Presentational UI/UX within explicitly assigned file scope: markup, styling, layout, design tokens, visual states, and presentational accessibility.
hivemind:local-reviewer Pre-PR reviewer Adversarial Codex review loop before the PR opens, up to 10 iterations. Fixes simple findings itself (two files or fewer), escalates complex ones, and stops on break-fix cycles. Needs the codex companion.
hivemind:github-reviewer Post-PR reviewer Stateless, one-shot post-PR worker: fetches and classifies review feedback, fixes, pushes, replies, and resolves threads. Dispatched by hivemind:github-review-loop.

05 Skills

Skills

All skills are invoked using the namespaced form hivemind:<skill-name>.

Skill Purpose
hivemind:route-workflow The sole workflow classifier: selects which workflow handles a non-Reflex request by judgment (never a keyword table), emitting selected, ambiguous, exploratory, or blocked.
hivemind:init-run-ledger State machine only. Initialize the run ledger for the current overlord instance: creates .hivemind/runs/<run-id>/ and writes the initial state.json via the committed engine script.
hivemind:record-state-result State machine only. Record the outcome of the current workflow state into the run ledger and advance state.current to the legal next state, validated against the workflow definition.
hivemind:next-wave State machine only (the standard-delivery script computes its waves in code, in plugin/workflow-src/lib/waves.js, with parity tests against this engine). Reads the run ledger and computes the ready wave: the maximal, file-disjoint set of dependency-satisfied plan steps to dispatch in parallel this iteration.
hivemind:mark-intent-fallback Sanctioned engine write path for the version-skew intent-fallback resume door and the start-fresh stale-run closeout: sets run.mode:intent_fallback, appends a fallback event, and optionally closes a stale run via run.status.
hivemind:create-working-branch Create or confirm a compliant working branch before implementation, through a committed script that refuses a dirty tree, an in-progress merge, rebase, cherry-pick, revert or bisect, and a working branch that is trunk, before any change. Used by both engines.
hivemind:gather-facts Report the branch as it is: branch state, its history against a freshly fetched trunk, the branch's PRs, and the text of any issue or PR the request names, in one complete facts file under .hivemind/facts/. The facts step of both workflow scripts, and run by the overlord before every cerebrate delegation on the state machine.
hivemind:molt Commit a completed phase, milestone, version bump, or review-remediation item through the committed molt.sh script, which commits exactly the listed files, refuses any other dirty path before it changes anything, and reports committed: false when there is nothing to commit. Used by both engines; in a workflow script it closes each wave and each gate step.
hivemind:bump-type Read-only engine for the overlord's version_bump_decision workflow state: derives the dominant Bump Type Determination row and bump verdict from the working-branch commits since the base. The Bump Trigger and No-bump judgments stay with the caller.
hivemind:push-branch Push the current working branch to its remote (no PR creation) through the committed push-branch.sh, which every push runs through and which refuses trunk; --expect-commit refuses when HEAD is another commit. Used to land remediation commits before resuming a review loop.
hivemind:open-plan-pr Open a pull request after completion, validation, and versioning gates pass, through a committed script that pushes through push-branch.sh, then reuses an open PR on the same head, base and commit (posting an optional comment there) or creates the PR, optionally as a draft, and verifies it. Used by both engines.
hivemind:adaptation-cycle Run a local pre-PR Codex review of the branch diff and return normalized findings. Review-only: it never fixes. Invoked by the local-reviewer agent only.
hivemind:github-review-loop Watch a PR in the main session and dispatch the fix-mode github-reviewer per actionable event. Owns the post-PR review loop.
hivemind:detect-remediation-signals Shared root-cluster, break-fix, diminishing-returns, and stop-and-merge detector over a fix-ledger. Emits one verdict both reviewers map to their own exit_reason.
hivemind:injection-scan Scan external-content items for prompt-injection and instruction-override attempts against the security-policy taxonomy; shared judgment skill used by both reviewer agents. Also scans issue and PR text in the branch facts before the planner reads it: the scan step of both workflow scripts, and on the state machine before each cerebrate delegation.
hivemind:decision-report State-machine runs only, because it reads the run ledger's decision journal. Render a chronological narrative of the auto-decisions a run made on your behalf, in the consumer project's domain language, and return it as chat text (writes nothing to disk). The automatic post-merge invocation is opt-in via HIVEMIND_ENABLE_DECISION_REPORT (see Configuration); invoking the skill explicitly works regardless of the key.
hivemind:plan-interrogation Interactive plan interview: challenges a plan against the project's domain model, sharpens terminology, and updates documentation (CONTEXT.md, ADRs) as decisions crystallise.
hivemind:create-handoff Generate an optional session-resumption handoff doc from a plan.
hivemind:plan-to-prd Turn an interrogated plan into a committed WHAT-only PRD.
hivemind:prd-to-issues Slice a PRD into vertically-sliced, brood-ready GitHub issues.
hivemind:triage-backlog Judgment-driven triage of the entire open GitHub issue backlog across 7 mutually exclusive label families (readiness, type, effort, moscow, priority, risk, difficulty) plus native GitHub issue dependencies. Renders a delta table, applies labels behind a confirm gate, and honors the human-only triage:locked control label.
hivemind:seed-hive Per-project setup: write required .claude/settings.json keys (enabledPlugins and default agent), gitignore .hivemind/ and .claude/worktrees/, confirm companions, seed the allowlist, invoke hivemind:creep-spread, and record the test command in CLAUDE.md.
hivemind:creep-spread Analyze project artifacts and generate a populated CONTEXT.md (or CONTEXT-MAP.md for multi-context repos) with domain terms extracted from code, docs, and config.
hivemind:zoom-out User-invoked only (model invocation disabled). Zoom out for broader context. Maps relevant modules and callers using the project's domain glossary vocabulary.
hivemind:spawn-brood Dispatch parallel overlord sessions: spawns N Claude Code instances in separate git worktrees via tmux and writes the brood manifest.
hivemind:brood-status Check status of broods under the current checkout, with per-strain status: tmux session state, branch existence, and PR status.
hivemind:enable-brood-remote User-invoked. Spawn already turns remote control on for the strains that started; on request, this skill sends the Claude /rc remote-control command again to every live strain in a brood (tmux keystroke injection).
hivemind:tdd Implement features using Test-Driven Development (TDD) with the red-green-refactor cycle. Invoke only in a context that can modify source and test files.
hivemind:improving-architecture Read-only architecture analysis: emits a ranked refactoring blueprint of deepening opportunities (shallow → deep modules) for testability and AI-navigability
hivemind:refactor-to-depth Execution skill that performs a behavior-preserving deepening refactor via a refactor-under-green loop, the in-implementation counterpart to the read-only improving-architecture blueprint

06 The Pipeline

The Lifecycle

hivemind:route-workflow selects the workflow first, for every request that is not a Reflex. One of two engines then runs it: when Claude Code's Workflow tool is available, analysis-only and standard-delivery launch as workflow scripts; every other workflow, and a request whose launch is refused, runs on its JSON state machine. analysis-only (hivemind:analysis-only) has been a script since 6.0.0, and standard-delivery (hivemind:standard-delivery) since 7.0.0. In manual mode the Workflow tool shows an approval prompt; in auto mode the launch goes ahead with no prompt. A No at the prompt interrupts the turn, with no fallback. To keep delivery on the state machine, add Workflow(hivemind:standard-delivery) to permissions.deny: the launch is refused with no prompt and the request falls back to the state machine. A script run keeps no run ledger: the working branch, its commits and the PR are the record, and its decisions go on the PR body. Only the state machine keeps a run ledger. A standard-delivery script run, from request to PR:

  1. Facts

    A runner gathers the branch facts into one facts file (hivemind:gather-facts).

  2. Scan

    A runner scans the text of the issues and PRs the request names for prompt injection (hivemind:injection-scan).

  3. Plan

    The cerebrate plans what is left of the request on this branch, and the plan is checked against plugin/references/plan-schema.json. Routine planner questions are decided by the autonomy table and listed as decided for you; only irreversible, architectural or safety-relevant questions, and hard stops, pause the run with a decision brief.

  4. Branch

    A runner creates or confirms the working branch (hivemind:create-working-branch) under feature/, bugfix/, hotfix/, refactor/, chore/, docs/, test/, or ci/. Nothing is ever committed to trunk.

  5. Waves

    Workers run each ready wave of plan steps in parallel, and a runner commits the wave's files after each wave (hivemind:molt).

  6. Bump

    A runner derives the version bump (hivemind:bump-type), a drone sets the version files, and a runner commits them.

  7. Validate

    A drone runs the project's validation commands. A failure gets a bounded number of fix rounds, one at a time, each one committed; after the last round the run asks you.

  8. Review

    The local reviewer reviews the branch and commits its simple fixes. It needs the codex companion.

  9. PR

    A runner pushes the commit every gate held on and opens its pull request, or reuses the open one (hivemind:open-plan-pr). The bump, validation and local review gates each hold only for the commit they ended on, so a later commit reruns the gates it invalidates. Every decision the run took for you is listed in the final message and in the PR body. Agents never merge. You do.

  10. State-machine fallback

    When the launch is refused, or the Workflow tool is absent, standard-delivery runs on its state machine instead: route, record a run ledger at .hivemind/runs/<run-id>/state.json, plan, git preflight and branch, build in waves with hivemind:next-wave, gate, review, ask you before the PR (pr_confirm), open the PR, and watch it. A Reflex (one owner, one known file, trivial change) skips the router, the run ledger, and the cerebrate.

You
 └─▶ Overlord  (route-workflow)
      ├─▶ Workflow script  (standard-delivery)
      │    ├─▶ Facts, scan  (gather-facts, injection-scan)
      │    ├─▶ Cerebrate  (plan, schema-checked)
      │    ├─▶ Working branch  (create or confirm)
      │    ├─▶ Drone / Changeling  (waves, one molt each)
      │    ├─▶ Gates on one commit  (bump, validate, local review)
      │    └─▶ PR opened or reused
      │         └─▶ github-review-loop  (default watch, state machine)
      │
      └─▶ State machine  (fallback: launch refused or no Workflow tool)

Workflows

Every non-Reflex request is routed to one workflow. standard-delivery and analysis-only have workflow scripts: each runs its script when the launch goes ahead, and its JSON state machine otherwise. The other workflows run only on their state machines, where the run ledger records where a run is and which transition comes next. The definitions live in plugin/workflows/: the .json state machines plus the generated .js scripts.

Workflow Handles
standard-delivery Change requests: plan, branch, build in waves, gate, review, ship, and watch the PR.
analysis-only Questions and analysis that change no files: analyze, then report.
pr-feedback-remediation Review feedback on an existing PR: watch it, or run a one-shot fix pass when you ask for one.
hatchery-dispatch Brood work: plan the strains, get your approval, spawn the brood, and monitor it.
exploratory-intent-session Requests whose intent is not yet clear: explore with you, checking in before anything is decided.

Waves

Each wave is the largest set of plan steps whose dependencies are done and whose file scopes do not overlap, so parallel workers never write the same file. Workers in a wave do not commit; one checkpoint commit (one molt) closes each wave, made by a runner in a script run and by the overlord on the state machine. On the state machine, hivemind:next-wave computes the wave from the run ledger; the standard-delivery script computes its waves in plugin/workflow-src/lib/waves.js.

Default PR watch

Watching is the default. It is off only when your original request explicitly says not to watch the PR, or when HIVEMIND_SKIP_PR_WATCH is set. When a script run opened or reused a PR, the overlord runs pr-feedback-remediation with intake watch on the state machine for that PR, a new run with its own run ledger. hivemind:github-review-loop dispatches the github-reviewer to fix, push, reply to, and resolve feedback from the Codex, Copilot, or Claude reviewer bots (reviewer_filter defaults to automated) until approval, merge, close, or an idle hour. max_watch_duration (default 3600 seconds) is an idle window, re-armed after each remediation cycle. A reviewer question or a high-severity rejection pauses the watch and asks you, and your answer resumes it, back at the GitHub reviewer. Agents never merge. merge-advised is advice to you.

07 Parallel Execution

Brood Mode

When the work is big enough, the overlord splits it into independent strains and dispatches a brood (multiple parallel sessions), each running its own full lifecycle in a separate git worktree. The overlord enters hatchery mode, monitoring from home base while each strain evolves independently.

How it works

  • The cerebrate decomposes work into independent strains with no shared state between them.
  • Approval gate: nothing spawns until you approve the strain list.
  • Each strain runs its own full overlord session in a detached tmux session. Brood children start in auto mode, so they launch the workflow scripts with no approval prompt, and fall back to the state machine as any session does.
  • Once a strain has started, spawn turns on remote control for it, so you can watch and answer it from claude.ai or the Claude app. Monitoring the brood is your job. Remote control needs a claude.ai subscription login. A strain that had not started when spawn ended needs hivemind:enable-brood-remote.
  • Each strain lives in its own git worktree (.claude/worktrees/<brood-id>/<short>), starts on a detached HEAD at the base, names its own branch, and produces its own PR.
  • The overlord stays in hatchery mode, monitoring the brood from home base and available as an on-demand helper.

hivemind:spawn-brood hivemind:brood-status

You
 └─▶ Overlord  (hatchery mode)
      └─▶ Cerebrate  (decompose)
           │  "3 independent strains detected."
           │
           ├─▶ Strain A  ─┐
           │    └─▶ own branch, own PR │
           ├─▶ Strain B  ─┤  parallel
           │    └─▶ own branch, own PR │
           └─▶ Strain C  ─┘
                └─▶ own branch, own PR

08 Framework Signals

Signals

Named states the swarm broadcasts. Each maps to a clear action.

Flare
Urgent: an agent hit something it cannot resolve alone. The overlord stops, surfaces the problem, and asks you how to proceed.
Requires human input
Reflex
Trivial task: one owner, one known file, no version impact. The overlord skips the router, the run ledger, and the cerebrate, and delegates the change directly.
Fast path
Mutation Decay
Fixes are fighting each other in a break-fix-break loop. Mandatory stop. You decide which direction to take.
Conflict detected
Creep Stagnation
Diminishing returns: each review pass yields less. An advisory early exit: the overlord stops the loop and opens the PR on its own, journals the call, and asks you only if the promotion gate trips.
Advisory
Root-Cluster
Several findings share one root. Instead of patching each instance, the swarm routes to one structural fix.
One structural fix
Merge-Advised
Only a bounded tail of findings remains on a hardened surface (the Stop-and-Merge rule). The loop recommends merging. Humans merge.
Advisory

10 Companion Plugins

Companion Plugins

All companions are optional. Hivemind works without them. Each one adds capabilities once it is installed and enabled for the project. hivemind:seed-hive enables it when you confirm that companion.

claude-mem

Optional cross-session memory and continuity. When enabled, the cerebrate reads claude-mem memory via the MCP search tools while planning, uses a forwarded Memory context: block instead when the overlord supplies one, and skips memory cleanly when claude-mem is absent. Writes happen through automatic capture, so no write tool is needed.

codex

Local pre-PR Codex review. Enables the local-reviewer agent, backed by hivemind:adaptation-cycle. That is all codex unlocks: the post-PR watch is the default and runs without codex. If codex is not enabled, local review is skipped gracefully.

11 Configuration

Configuration

Optional environment variables. Set them in the env block of .claude/settings.json (committed, so it also applies inside brood worktrees) or .claude/settings.local.json (gitignored, per-account). Leaving one unset keeps the default behavior. To keep a workflow on the state machine, add a Workflow(hivemind:analysis-only) or Workflow(hivemind:standard-delivery) entry to permissions.deny in either file: the launch is then refused with no prompt, and the overlord says so in one line and runs the request on the state machine.

Variable Effect
HIVEMIND_LOCAL_REVIEW_MODEL Overrides the model for local Codex review. Empty or unset: codex uses its own default. The value must match ^[a-zA-Z0-9/_.\-]+$.
HIVEMIND_SKIP_PR_WATCH When set to any non-empty value, the overlord never watches PRs after opening them. Unset or empty: the default post-PR watch runs.
HIVEMIND_ENABLE_DECISION_REPORT Covers state-machine runs only: workflow-script runs keep no run ledger, so the report does not see them, and they show their decisions in the final message and the PR body instead. When set to any non-empty value, the overlord shows the post-merge decision report. Unset or empty: the report is off; the decision journal in the run ledger is still written. 
{
  "env": {
    "HIVEMIND_SKIP_PR_WATCH": "1"
  }
}
