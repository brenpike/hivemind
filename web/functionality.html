01 Install

Install inside Claude Code

Run these two commands inside an active Claude Code session. Then run /hivemind:seed-hive once in each project (see Per-project setup). 

/plugin marketplace add https://github.com/brenpike/hivemind.git
/plugin install hivemind@brenpike

Version control

Host

03 Per-project setup

Per-project setup

1. Enable in .claude/settings.json

Add two keys to your project's .claude/settings.json. The agent key sets the overlord as the session default. Without it, Claude Code starts with the default agent and the overlord is only reachable on-demand, which bypasses the workflow guarantees. 

{
  "enabledPlugins": {
    "hivemind@brenpike": true
  },
  "agent": "hivemind:overlord"
}

Or run the one-shot setup skill: 

/hivemind:seed-hive
  • ◆ Writes the enabledPlugins and agent keys into .claude/settings.json
  • ◆ Gitignores .hivemind/ and .claude/worktrees/
  • ◆ Detects companion plugins (caveman, claude-mem, codex) and asks once, in one consolidated confirmation; headless runs auto-enable detected companions
  • ◆ Seeds a least-privilege permission allowlist, on by default (see 1a)
  • ◆ Invokes hivemind:creep-spread to generate your domain glossary (CONTEXT.md)
  • ◆ Records the detected test command under ## Validation in CLAUDE.md when it is absent

.hivemind/ holds runtime state (run ledgers, plans, handoffs, and brood manifests) and is gitignored so it is never committed.

1a. Least-privilege permission allowlist (on by default)

seed_allowlist is on by default: seed-hive merges a recommended set of permissions.allow entries: read-only helpers like echo, grep, jq, and scoped git read subcommands. Entries are appended-if-absent; existing entries are never overwritten or removed. To skip the allowlist: 

/hivemind:seed-hive seed_allowlist=no

The supported setup for local Codex review is a per-contributor grant: add your Codex cache path to the gitignored .claude/settings.local.json: 

"Bash(node /path/to/.claude/plugins/cache/openai-codex/codex/*)"

Replace /path/to/ with your actual home directory path. The codex/* wildcard covers all Codex CLI entry points so the entry does not need updating when Codex is upgraded.

See the README setup section for the full rationale and the upgrade path for already-seeded projects.

📄

Step 2 Create CLAUDE.md

Add project-specific details the swarm uses every session:

  • ◆ Build and test commands
  • ◆ Package names and version file paths
  • ◆ Versioning configuration (bump triggers, changelogs, tag prefixes)
  • ◆ Architecture and code style notes
🔎

Step 3 Create AGENTS.md

Add project-specific Codex reviewer guidance at the repo root:

  • ◆ Review focus areas
  • ◆ Severity definitions
  • ◆ Project-specific conventions for reviewers
04 Agents

Agents

Four bioforms plus two reviewer agents. Each owns a distinct role. Agents are addressed as hivemind:<agent>.

Agent Role What it does
hivemind:overlord Orchestrator Session default and your main interface. Routes each request to a workflow, runs the workflow state machine and its run ledger, and owns branches, checkpoint commits, version bumps, PRs, and review routing. Delegates all implementation. Never writes code.
hivemind:cerebrate Strategist Read-only research and planning. Never writes files. Returns the directive: STEP-NNN steps with exact file scopes, dependencies, risks, and a delivery shape (single, multi, or brood).
hivemind:drone Builder Implements code, fixes bugs, refactors, and updates tests and release metadata within explicitly assigned file scope. Default owner of every step.
hivemind:changeling Shaper Presentational UI/UX within explicitly assigned file scope: markup, styling, layout, design tokens, visual states, and presentational accessibility.
hivemind:local-reviewer Pre-PR reviewer Adversarial Codex review loop before the PR opens, up to 10 iterations. Fixes simple findings itself (two files or fewer), escalates complex ones, and stops on break-fix cycles. Needs the codex companion.
hivemind:github-reviewer Post-PR reviewer Stateless, one-shot post-PR worker: fetches and classifies review feedback, fixes, pushes, replies, and resolves threads. Dispatched by hivemind:github-review-loop.
05 Skills

Skills

All skills are invoked using the namespaced form hivemind:<skill-name>.

Skill Purpose
hivemind:route-workflow The sole workflow classifier: classifies a request and selects the workflow that handles it, emitting selected, ambiguous, exploratory, or blocked.
hivemind:init-run-ledger Create the run ledger for a new run at .hivemind/runs/<run-id>/state.json.
hivemind:record-state-result Record a workflow state's outcome in the run ledger, validate the transition against the workflow definition, and advance to the legal next state.
hivemind:next-wave Compute the next wave of ready, dependency-met, file-disjoint plan steps to dispatch in parallel.
hivemind:mark-intent-fallback Record a version-skew intent-fallback event in the run ledger on resume, and optionally close a stale run.
hivemind:create-working-branch Create or confirm a compliant working branch before implementation begins.
hivemind:molt Commit a completed phase, milestone, version bump, or review-remediation item (the checkpoint commit skill).
hivemind:bump-type Derive the bump verdict and bump type from the branch's commits, using the Bump Trigger and No-bump judgments the overlord passes in.
hivemind:push-branch Push the working branch to its remote without opening a PR. Used when a review loop resumes with remediation commits.
hivemind:open-plan-pr Open a pull request after completion, validation, and versioning gates pass.
hivemind:adaptation-cycle Run a local pre-PR Codex review of the branch diff and return normalized findings. Review-only: it never fixes. Invoked by the local-reviewer agent only.
hivemind:github-review-loop Watch a PR in the main session and dispatch the fix-mode github-reviewer per actionable event. Owns the post-PR review loop.
hivemind:detect-remediation-signals Read a fix-ledger and return one verdict on break-fix, root-cluster, diminishing-returns, and stop-and-merge signals before the next patch.
hivemind:injection-scan Scan external content (PR comments, review bodies, findings) for prompt-injection attempts and return a verdict per item.
hivemind:decision-report After a run's PR merges or closes, render a plain-language narrative of the auto-decisions the run made on your behalf. Opt-in via HIVEMIND_ENABLE_DECISION_REPORT.
hivemind:plan-interrogation Interactive plan interview: challenges a plan against the project's domain model, sharpens terminology, and updates documentation as decisions crystallise.
hivemind:create-handoff Generate an optional session-resumption handoff doc from a plan.
hivemind:plan-to-prd Turn an interrogated plan into a committed WHAT-only PRD.
hivemind:prd-to-issues Slice a PRD into vertically-sliced, brood-ready GitHub issues.
hivemind:triage-backlog Rate every open issue across mutually exclusive label families, infer depends-on links, show a delta table, and apply labels behind a confirm gate.
hivemind:seed-hive One-time project setup: write required .claude/settings.json keys, gitignore .hivemind/ and .claude/worktrees/, detect companions, seed the permission allowlist, run creep-spread, and record your test command.
hivemind:creep-spread Analyze project artifacts and generate a populated CONTEXT.md (or CONTEXT-MAP.md for multi-context repos) with domain terms extracted from code, docs, and config.
hivemind:zoom-out User-invoked only. Zoom out for broader context. Maps relevant modules and callers using the project's domain glossary vocabulary.
hivemind:spawn-brood Dispatch parallel overlord sessions: spawns N Claude Code instances in separate git worktrees via tmux and writes the brood manifest.
hivemind:brood-status Read-only hatchery dashboard: each strain's tmux session state, branch existence, and PR status for every brood under the current checkout.
hivemind:enable-brood-remote On your explicit request only, enable remote control for every strain of a brood by sending /rc <strain-name> to each live session.
hivemind:tdd Implement features using Test-Driven Development (TDD) with the red-green-refactor cycle. Invoke only in a context that can modify source and test files.
hivemind:improving-architecture Read-only architecture analysis: emits a ranked refactoring blueprint of deepening opportunities (shallow → deep modules) for testability and AI-navigability
hivemind:refactor-to-depth Execution skill that performs a behavior-preserving deepening refactor via a refactor-under-green loop, the in-implementation counterpart to the read-only improving-architecture blueprint
06 The Pipeline

The Lifecycle

A task flows from you through a chain of specialists, driven by a workflow state machine. Each hand-off is explicit: the cerebrate produces a directive; drones and changelings build it in waves; gates and review close the loop before shipping. The standard-delivery run:

  1. 01
    Route.

    hivemind:route-workflow picks the workflow for your request (see the table below). A trivial change takes the Reflex fast path, which skips the router, the run ledger, and the cerebrate.

  2. 02
    Record.

    The run ledger lives at .hivemind/runs/<run-id>/state.json. Each state result is normally validated against the workflow definition before the run advances.

  3. 03
    Plan.

    The read-only cerebrate researches the codebase and returns a directive: steps with exact file scopes, dependencies, risks, and a delivery shape.

  4. 04
    Branch.

    Git preflight, then a working branch under feature/, bugfix/, hotfix/, refactor/, chore/, docs/, test/, or ci/. The overlord never commits to trunk.

  5. 05
    Build in waves.

    hivemind:next-wave picks the ready steps; drones and changelings build them in parallel, each within an explicit file scope. One molt per wave.

  6. 06
    Gate.

    The overlord makes the versioning judgments and hivemind:bump-type derives the bump verdict from the branch's commits, then the project's validation commands run.

  7. 07
    Review.

    When codex is installed, the local-reviewer runs its adversarial adaptation cycle on the branch diff before any PR exists. Without codex, this step is skipped.

  8. 08
    Ship and watch.

    The overlord opens the PR and watches it by default (see below). Agents never merge. You do.

You
 └─▶ Overlord  (route, record)
      ├─▶ Cerebrate       (plan)
      │    └─▶ Directive
      │
      ├─▶ Working branch  (preflight)
      │
      ├─▶ Drone / Changeling  (build)
      │    └─▶ Waves, one molt each
      │
      ├─▶ Gates  (bump-type, validation)
      │
      ├─▶ Local-Reviewer  (if codex)
      │    ├─▶ Simple findings fixed
      │    └─▶ Complex findings escalated
      │
      └─▶ PR opened
           └─▶ github-review-loop  (default watch)

Workflows

Every non-Reflex request is routed to one workflow. Each workflow is a state machine; the run ledger records where a run is and which transition comes next.

Workflow Handles
standard-delivery Change requests: plan, branch, build in waves, gate, review, ship, and watch the PR.
analysis-only Questions and analysis that change no files: analyze, then report.
pr-feedback-remediation Review feedback on an existing PR: watch it, or run a one-shot fix pass when you ask for one.
hatchery-dispatch Brood work: plan the strains, get your approval, spawn the brood, and monitor it.
exploratory-intent-session Requests whose intent is not yet clear: explore with you, checking in before anything is decided.
🌊

Waves

Inside one run, the overlord builds in waves. hivemind:next-wave reads the run ledger and returns every step that is ready, has its dependencies met, and touches files no other wave member touches. The whole wave is dispatched in parallel; workers never commit, and the overlord molts one checkpoint per wave.

👁

Default PR watch

After opening a PR, the overlord watches it by default with hivemind:github-review-loop. Actionable feedback from Codex, Copilot, or Claude reviewer bots is fixed, pushed, replied to, and resolved by the github-reviewer, until approval, merge, close, or an idle hour. Opt out by saying so in your request, or set HIVEMIND_SKIP_PR_WATCH. Agents never merge.

07 Parallel Execution

Brood Mode

When the work is big enough, the overlord splits it into independent strains and dispatches a brood (multiple parallel sessions), each running its own full lifecycle in a separate git worktree. The overlord enters hatchery mode, monitoring from home base while each strain evolves independently.

How it works

  • ◆ The cerebrate decomposes work into independent strains with no shared state between them.
  • ◆ Approval gate: nothing spawns until you approve the strain list.
  • ◆ Each strain runs its own full overlord session in a detached tmux session.
  • ◆ Each strain lives in its own git worktree (.claude/worktrees/<brood-id>/<short>) and produces its own branch and PR.
  • ◆ The overlord stays in hatchery mode, monitoring the brood from home base and available as an on-demand helper.
hivemind:spawn-brood hivemind:brood-status 
You
 └─▶ Overlord  (hatchery mode)
      └─▶ Cerebrate  (decompose)
           │  "3 independent strains detected."
           │
           ├─▶ Strain A  ─┐
           │    └─▶ own branch, own PR │
           ├─▶ Strain B  ─┤  parallel
           │    └─▶ own branch, own PR │
           └─▶ Strain C  ─┘
                └─▶ own branch, own PR
08 Framework Signals

Signals

Named states the swarm broadcasts. Each maps to a clear action.

🔥

Flare

Urgent: an agent hit something it cannot resolve alone. The overlord stops, surfaces the problem, and asks you how to proceed.

Requires human input
⚡

Reflex

Trivial task: one owner, one known file, no version impact. The overlord skips the router, the run ledger, and the cerebrate, and delegates the change directly.

Fast path
🧬

Mutation Decay

Fixes are fighting each other in a break-fix-break loop. Mandatory stop. You decide which direction to take.

Conflict detected
🐌

Creep Stagnation

Diminishing returns: each review pass yields less. An advisory early exit: the loop hands the keep-going decision back to you.

Advisory
🌱

Root-Cluster

Several findings share one root. Instead of patching each instance, the swarm routes to one structural fix.

One structural fix
🔀

Merge-Advised

Only a bounded tail of findings remains on a hardened surface (the Stop-and-Merge rule). The loop recommends merging. Humans merge.

Advisory

10 Companion Plugins

Companion Plugins

All companions are optional. Hivemind works without them. When installed, each unlocks additional capabilities.

🧠

claude-mem

Optional cross-session memory and continuity. When installed, the cerebrate reads claude-mem memory via the MCP search tool before every plan. Writes happen through automatic capture, so no write tool is needed.

GitHub ↗
Optional
🔎

codex

Local pre-PR Codex review. Enables the local-reviewer agent, backed by hivemind:adaptation-cycle. That is all codex unlocks: the post-PR watch is the default and runs without codex. If not installed, local review is skipped gracefully. 

/plugin marketplace add https://github.com/openai/codex-plugin-cc.git
/plugin install codex@openai-codex
/reload-plugins
/codex:setup
Optional
🕯

caveman

Token-compressed communication. When installed, all framework agents output in caveman ultra mode, dramatically reducing token usage while preserving full technical accuracy. 

"enabledPlugins": { "caveman@caveman": true },
"pluginConfigs": { "caveman@caveman": {
  "options": { "defaultLevel": "ultra" } } }

11 Configuration

Configuration

Optional environment variables. Set them in the env block of .claude/settings.json (committed, so it also applies inside brood worktrees) or .claude/settings.local.json (gitignored, per-account). Leaving one unset keeps the default behavior.

Variable Effect
HIVEMIND_LOCAL_REVIEW_MODEL Overrides the model for local Codex review. Empty or unset: codex uses its own default. The value must match ^[a-zA-Z0-9/_.\-]+$.
HIVEMIND_SKIP_PR_WATCH When set to any non-empty value, the overlord never watches PRs after opening them. Unset or empty: the default post-PR watch runs.
HIVEMIND_ENABLE_DECISION_REPORT When set to any non-empty value, the overlord shows the post-merge decision report. Unset or empty: the report is off; the decision journal is still written. 
{
  "env": {
    "HIVEMIND_SKIP_PR_WATCH": "1"
  }
}
