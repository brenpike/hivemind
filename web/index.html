Claude Code Plugin

Hivemind

Multi-agent orchestration framework for Claude Code. Coordinates specialized bioforms to plan, build, review, and ship code, so you don't have to manage the pipeline yourself.

Install inside Claude Code

/plugin marketplace add https://github.com/brenpike/hivemind.git
/plugin install hivemind@brenpike

Then run /hivemind:seed-hive once in each project.

The Swarm

Know Your Bioforms

Four bioforms plus two reviewer agents. Each owns a distinct role in the pipeline. None overlap. Together they close the loop from directive to PR.

👁

Overlord

The control plane and session default. Routes each request to a workflow, runs the workflow state machine and its run ledger, and owns branches, checkpoint commits, version bumps, PRs, and review routing. Delegates all implementation. Never writes code. Your main interface.

Orchestrator
🧠

Cerebrate

Originates the plan. Researches the codebase and returns the directive: STEP-NNN steps with exact file scopes, dependencies, risks, and a delivery shape: single, multi, or brood. Read-only: thinks, never writes files.

Strategist
🔨

Drone

The workhorse and default owner of every step. Implements code, fixes bugs, refactors, and updates tests and release metadata, strictly within its assigned file scope.

Builder
🎮

Changeling

Presentational UI/UX within assigned scope: markup, styling, layout, design tokens, visual states, and presentational accessibility. Reshapes how things look and feel.

Shaper
🔎

Local-Reviewer

Pre-PR adversarial Codex review loop, up to 10 iterations. Fixes simple findings itself (two files or fewer), escalates complex ones, and stops on break-fix cycles. Needs the codex companion.

Pre-PR reviewer
💬

GitHub-Reviewer

Post-PR, stateless, one-shot. Fetches and classifies review feedback, fixes, pushes, replies, and resolves threads. Dispatched by hivemind:github-review-loop.

Post-PR reviewer

The Pipeline

The Lifecycle

  1. 01 Route: the Overlord sends your request to a workflow; a Reflex fast path skips routing for trivial changes
  2. 02 Record: a run ledger tracks the run; every state result is validated against the workflow definition
  3. 03 Plan: the Cerebrate researches the codebase and returns a directive
  4. 04 Branch: git preflight, then a compliant working branch; never a commit to trunk
  5. 05 Build in waves: Drones and Changelings take ready, file-disjoint steps in parallel, one molt per wave
  6. 06 Gate: the overlord makes the versioning judgments, bump-type derives the bump verdict, then validation runs
  7. 07 Review: the Local-Reviewer runs an adaptation cycle when codex is installed
  8. 08 Ship and watch: the PR opens and is watched by default. Agents never merge. You do. 
You
 └─▶ Overlord  (route, record)
      ├─▶ Cerebrate  (plan)
      │    └─▶ Directive
      ├─▶ Working branch  (preflight)
      ├─▶ Drone / Changeling  (build)
      │    └─▶ Waves, one molt each
      ├─▶ Gates  (bump-type, validation)
      ├─▶ Local-Reviewer  (review, if codex)
      └─▶ PR  (watched by default)
Parallel Execution

Brood Mode

When work is big enough, the Overlord splits it into independent strains and dispatches a brood: parallel sessions, each running its own full lifecycle in a separate git worktree.

How it works

  • ◆ Cerebrate decomposes work into independent strains with no shared state between them
  • ◆ Approval gate: nothing spawns until you approve the strain list
  • ◆ Each strain runs its own overlord in its own worktree (.claude/worktrees/<brood-id>/<short>) and detached tmux session
  • ◆ Each strain produces its own branch and PR
  • ◆ The Overlord enters hatchery mode, watching strains via hivemind:brood-status 
You
 └─▶ Overlord  (hatchery mode)
      └─▶ Cerebrate  (decompose)
           │  you approve the strains
           ├─▶ Strain A  ┐
           │    └─▶ own branch, own PR
           ├─▶ Strain B  ├─ parallel
           │    └─▶ own branch, own PR
           └─▶ Strain C  ┘
                └─▶ own branch, own PR
Framework Signals

Signals

Named states the swarm broadcasts. Each maps to a clear action.

🔥

Flare

Urgent: an agent hit something it cannot resolve alone. The Overlord stops and asks you.

Requires human input
⚡

Reflex

Trivial task: one owner, one known file, no version impact. The Overlord skips the router, the run ledger, and the Cerebrate, and delegates the change directly.

Fast path
🧬

Mutation Decay

Break-fix-break: fixes keep re-breaking each other. Mandatory stop. You decide which path to take.

Conflict detected
🐌

Creep Stagnation

Diminishing returns: each review pass yields less. An advisory early exit; the call comes back to you.

Advisory
🌱

Root-Cluster

Several findings share one root. Instead of patching each, the swarm reaches for one structural fix.

One structural fix
🔀

Merge-Advised

Only a bounded tail of findings remains on a hardened surface (the Stop-and-Merge rule). The loop recommends merging. Humans merge.

Advisory
