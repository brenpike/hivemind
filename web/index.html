Hivemind

Claude Code plugin

Multi-agent orchestration framework for Claude Code. Coordinates specialized bioforms to plan, build, review, and ship code, so you don't have to manage the pipeline yourself.

You are the Overmind. The swarm acts on your intent.

Install the swarm View on GitHub

Move or touch to scatter the swarm. Press and hold to call it to you. Tap a heading to re-encode it.

The six forms

One mind, six specialised forms

Four bioforms and two reviewer composites. The overlord is the hub; every other form is a spoke it dispatches. Hover or tap a form to light its cluster.

  • Overlord

    Orchestrator

    Bioform · hivemind:overlord · session default

    Routes each request to a workflow, then launches its workflow script or runs the workflow state machine and its run ledger. Owns branches, checkpoint commits, version-bump decisions, PRs and review routing. It delegates all implementation and never writes code.

  • Cerebrate

    Strategist · read-only

    Bioform

    Researches the codebase and returns the directive: STEP-NNN steps with exact file scopes, dependencies, risks and a delivery shape (single, multi or brood). Has no shell: its tools are Read, Glob, Grep, LSP, the web tools and the claude-mem search tools. Takes branch state only from the facts file. Never writes files.

  • Drone

    Builder

    Bioform

    Implements code, fixes bugs, refactors, and updates tests and release metadata within an explicitly assigned file scope. The default owner of every step. Inside workflow scripts, it also runs the facts and git steps.

  • Changeling

    Shaper

    Bioform

    Presentational UI/UX: markup, styling, layout, design tokens, visual states and presentational accessibility, within an assigned file scope.

  • Local-Reviewer

    Pre-PR

    Reviewer composite

    Runs an adversarial Codex review loop before the PR exists, up to 10 iterations. Fixes simple findings (2 files or fewer), escalates complex ones, and stops on break-fix cycles. Needs the codex companion.

  • GitHub-Reviewer

    Post-PR · one-shot

    Reviewer composite · stateless

    Fetches and classifies review feedback, fixes, pushes, replies and resolves threads. Dispatched by the hivemind:github-review-loop skill.

standard-delivery

How a run works

Eight beats from your intent to a reviewed pull request, as a standard-delivery workflow script run. A script run keeps no run ledger: the working branch, its commits and the PR are the record. When the launch is refused, or the Workflow tool is absent, standard-delivery runs on its state machine instead, and only that path keeps a run ledger.

  1. Route

    hivemind:route-workflow picks standard-delivery, analysis-only, pr-feedback-remediation, hatchery-dispatch or exploratory-intent-session. Analysis-only and standard-delivery launch as the hivemind:analysis-only and hivemind:standard-delivery workflow scripts when Claude Code's Workflow tool is available; every other workflow runs on its state machine.

    Analysis-only has been a script since 6.0.0, standard-delivery since 7.0.0. In manual mode the Workflow tool shows an approval prompt; in auto mode the launch goes ahead with no prompt. A No at the prompt interrupts the turn, with no fallback. To keep delivery on the state machine, add Workflow(hivemind:standard-delivery) to permissions.deny: the launch is refused with no prompt and the request falls back to the state machine. The definitions live in plugin/workflows/: .json state machines plus the generated .js scripts.

    A trivial one-file change takes the Reflex fast path, which skips the router, the run ledger and the cerebrate.

  2. Facts

    A runner gathers the branch facts into one facts file (hivemind:gather-facts), then scans the text of the issues and PRs the request names for prompt injection (hivemind:injection-scan).

  3. Plan

    The cerebrate plans what is left of the request on this branch, and the plan is checked against plugin/references/plan-schema.json. After a pause, the planner revises the plan with your reply.

  4. Branch

    A runner creates or confirms a compliant working branch (hivemind:create-working-branch): feature/, bugfix/, hotfix/, refactor/, chore/, docs/, test/, ci/.

    The swarm never commits to trunk.

  5. Build in waves

    Each wave is the largest set of plan steps whose dependencies are done and whose file scopes do not overlap. Drones and changelings build it in parallel, and a runner commits the wave's files with one checkpoint commit (molt) per wave (hivemind:molt). The script computes each wave in plugin/workflow-src/lib/waves.js; on the state-machine fallback, hivemind:next-wave reads it from the run ledger.

  6. Gate

    A drone runs the project's validation commands and checks the version read-only with hivemind:bump-type --version-file. A failure gets a bounded number of fix rounds, each one committed; after the last round the run asks you.

    The validation (with its version check) and local review each hold only for the commit they ended on, and the PR step pushes only a commit every configured gate held on. A later commit reruns the gates it invalidates.

  7. Review

    The local-reviewer reviews the branch and commits its simple fixes. Needs the codex companion.

  8. Ship and watch

    A runner pushes the commit every gate held on and opens its pull request, or reuses the open one (hivemind:open-plan-pr). Every decision the run took for you is listed in the final message and in the PR body.

    The overlord then watches the PR by default. It fixes, pushes, replies to and resolves actionable feedback from Codex, Copilot or Claude reviewer bots until reviewer approval, merge, close, or an idle hour.

    Opt out by saying so in the request or by setting HIVEMIND_SKIP_PR_WATCH. Agents never merge. You do.

Parallel strains

Brood

The cerebrate splits big work into independent strains. After you approve, each strain runs as its own overlord in its own git worktree (.claude/worktrees/<brood-id>/<short>) and its own detached tmux session, with its own branch and PR. Each strain starts in auto mode, so it launches the workflow scripts with no approval prompt. Once a strain has started, spawn turns on remote control for it, so you can watch and answer it from claude.ai or the Claude app; monitoring the brood is your job. The hatchery watches via hivemind:brood-status.

Who decides

Autonomy

Routine calls are decided for you by the autonomy table and listed on the PR. Irreversible, architectural or safety-relevant calls pause the run and ask you, and every merge comes back to you. Every open question pauses a delivery run and your reply resumes the same run, with no pause limit, while an analysis-only run completes after 3 pauses and lists the questions still open.

What the swarm tells you

Signals

Flare
An agent can't safely resolve something; the overlord stops and asks you.
Reflex
The trivial fast path.
Mutation Decay
Fixes undo each other, break-fix-break. A mandatory stop.
Creep Stagnation
Diminishing returns. An advisory early exit.
Root-Cluster
Several findings share one root; plan one structural fix.
Merge-Advised
A bounded tail remains; the swarm recommends merge, humans merge.

Install

Three commands in Claude Code. Select a command to copy it.

01 Add the marketplace

/plugin marketplace add https://github.com/brenpike/hivemind.git

02 Install the plugin

/plugin install hivemind@brenpike

03 Seed each project

/hivemind:seed-hive

Run the first two once in Claude Code, then seed the hive in each project. Seeding merges a least-privilege allowlist, with Edit(.hivemind/...) rules such as Edit(.hivemind/molt-inputs-*.json) and Edit(.hivemind/pr-inputs-*.json) that pre-approve only the inputs files skills write.

Requires

  • bash (macOS, Linux or WSL)
  • git, gh and jq
  • The Claude Code CLI
  • tmux: only for brood mode
  • node: only for the optional local Codex review

Optional companions

  • claude-mem: memory
  • codex: local pre-PR review
  • caveman: compressed output
